## 1. 缺陷类别（最常犯，括号内是"回忆触发"）

## 2. 工具与编码坑（每轮都可能踩）

| 坑 | 一句话做法 |
|---|---|
| JSON 里写 ASCII 引号 | 用中文引号 `“”`，或转义 |
| Python 三引号尾部 `""""` | 新串以 `"` 收尾时，**终止三引号另起一行** |
| 补丁锚串过期（上一轮改/回退过） | 改补丁前先 `read` 当前文本；或先跑**内存复现探针** |
| `patch --check` 不校验 JSON | 落盘后立即复验；先在内存里 `json.loads` 一遍 |
| 补丁没落盘就跑套件 | 先看输出有没有 `[写入]`，再决定跑不跑 |
| 生成端截断输出 | **一次运行全量结构化留档**（`dev.py` 自动写 `logs/<cmd>-<时间戳>.log` 与 `logs/<cmd>-latest.json`），后续用 `tools/readback.py` 读 |
| 改数据用文本锚串 | 改用 `tools/jsondb.py` **按键路径**改（锚串撞车/尾部换行/引号三类坑一次性消除） |
| PowerShell 管道重写源文件 | 中文会变乱码 ⟹ 只用 `write`/`edit` 工具 |
| **PowerShell `>` / `Out-File` 写 UTF-16** | `git show … > x.json` 出来首字节 `FF FE`，`json.load` 直接崩 ⟹ **不要用重定向**：`dev.py` 已自动写 `logs/`；要提取 git 内容就用 Python 写字节 |
| 编码异常静默混入（BOM/UTF-16/NUL） | `dev.py hygiene` 现在会**报出来**，`--fix` 就地重写为无 BOM UTF-8 |
| `git commit -m "…中文引号…"` | 写消息文件，`git commit -F` |
| 工具名与 stdlib 同名 | `tools/` 会成为 `sys.path[0]` ⟹ 禁止 `inspect.py`/`json.py` 这类名字 |
| 探针里用 `__file__` | `dev.py patch` 的 exec 环境没有它；spec 只放 `PATCHES` |
| **手工猜诊断参数** | 探针的 `(ledger, He)` 必须**取自真实运行**：`CHEM_TRACE=1` 的 `[micro]`/`[micro-led]` 行给出禁用点的 He 与账本；猜参数会诊到走步根本没经过的态 |
| **记忆里的常引值** | **记忆值不得当已核数据**：第 153 轮按记忆写草酸 ΔH₂ = **+7.0**，使用者给出文献值实为 **−7.3**（二级电离**放热**）——符号都错了。查不到确切出处时，宁可**不入库**（宁缺勿错），要入就写 `calibrated: provenance 未核实` 并单列待复核 |
| **测试库标准 = 旧引擎快照** | 数据补全后翻红的标准，先问"这是化学事实还是快照"：第 153 轮 `NR114`/`Hyd3` 的 `changed=False` 与"期望 Cr(OH)₃"都是**引擎未含显式一级水解时**的产物，实测 Cr³⁺ 1 M 水解 1% ⟹ pH 2.0 下不可能沉淀 ⟹ 标准错、按化学事实重裁 |
| 控制台 GBK | 脚本走 `dev.py run`；控制台只打 ASCII |
| **依赖进程输出的管道** | `python … \| Select-String` 要等进程退出才回显（像挂住/触发超时）⟹ 别管道，事后读 `logs/` 里的自动留档 |
| **临时探针** | 一次写对：真文件可 `git checkout --` 回退，就别把函数体复制进探针；A/B 要在**同一进程换函数引用**跑、末尾断言已还原 |
| **加闸/守卫** | 先按最简判据量全量、再按**实测命中点**收紧（两次全量 ~40 s，比事后猜"是不是它干的"便宜）；判据要**自洽性**，不是"存在/量够" |
| **回退到已知状态** | **不要重测**：结果已知（git 快照 + 上一轮留档），重跑全量是纯浪费；只在"回退后还要改动"时才跑 |
| **储库接管要守恒**（第 199 轮） | 用精确解接管储库自由度时，**只删游离离子而冻结其配合物 = 幻影配平**（电荷平衡会凭空造出游离离子：E55 造出 0.25 M Al³⁺、case 16 抬到 pH 12.3）。正确做法三件套：该金属**全配体配合物从属钉住浓度**（梯项进方程）＋**非 OH⁻ 配体量返还账本**（配体守恒）＋**储库耗尽回检**（溶解总量>库存则"固相在场"前提不成立）。第 200 轮已补全三件套（`_pin_frozen`）。同理警惕"无限储库"假设——账本固相 1e-4 mol 时钉住项不能当无限源 |
| **精确解有效窗口 = \|He\|≈0**（第 200 轮） | `charge_pH`（含 pinned）**不看 He**：\|He\| 大时账本电荷严重不平衡，精确解是配平幻觉（B26 步首 He=−2 时钉住会报 pH 1.52，真实 ~14.3）——h_c≈o_c 退化区闸**不能去** |
| **ROOT_AUDIT 细扫字段** | 61 点细扫的 5 元组 = `(x, pH, 固相在场, tag, 账本电荷+He)`——**第 5 元不是 S**，是守恒审计量（恒 ≈0 为正常） |
| **speciation 内部调用可 spy** | `charge_pH` 这类 **speciation 模块内自调用**，patch `speciation.charge_pH` 模块属性即生效（模块全局名查找）；但 engine 对 `estimate_pH`/`estimate_state` 是**按名导入**，patch 无效（旧坑）。探针捕获真实 `(ledger, pinned)` 用前者 |
| **调容差去凑悬崖宽度** | 阈值拟合：容差放大到把悬崖盖住 ⟹ 打红别的体系（X-45 的 1e-2 打红 H88）。修法要能**区分来源**，不是把尺子挪到问题变小 |
| **模块级补丁打不动走步** | `engine.py` 对 `estimate_pH`/`estimate_state`/`_buffer_titration` 是**按名导入**的：改 `speciation.<名字>` 对**走步热路径无效**（只有 speciation 内部自调用受影响）⟹ 探针会跑出**假阴性**（第 151 轮 `estimate_pH` 0 次调用、第 157 轮判据 C 无效，同一个坑踩两次）。要么打引擎真正调用的引用，要么直接改真文件 |
| **数据与标准冲突** | 不自行裁决：入库→发现打红→**用 `ask_user_question` 把两侧证据一并摆出**（引擎值 vs 标准值 + 解析核对），由使用者定"改数据"还是"重裁标准"。两套 pKw 约定**同时**打红同一批 ⟹ 是取值冲突，不是约定/引擎缺陷 |
| **条件常数 ≠ 标准态常数** | 本库 β 一律 **I→0**，引擎**没有离子强度层**：把 I=3 的条件值塞进 I→0 槽位 ⟹ 第 166 轮 34 例 Fe(III)-Cl 翻红（Fe–Cl 的 I 依赖可达 80 倍）。文献给"条件值/方程"时必须先换算或**要 I→0 值**；同理 Fe(III)–Cl 的 Byrne 第二式是**逐级 K₂**（累积 β₂ = logβ₁+logK₂，可小于 logβ₁）——把逐级当累积是第二次踩 |
| **自查 assert 要先验算** | 第 166 轮我写了 `assert β₂ > β₁`，而 K₂<1 时累积 β₂ 本就该**小于** β₁ ⟹ 自己把自己拦下并误以为数据错。**先手算一个例子再写断言** |
| **动手前先做反例预测** | 判据写完先问"**已知的哪一族会落在同一条判据里**"（X-45 判据 B 只顾 D47，写完才发现 Al³⁺ 碱量不足族的游离池与账本侧也接近 ⟹ 12 例翻红）。守卫类判据两版都被否 = 方向需换，不是继续调参 |
| **探针 pH ≠ 走步 pH**（第 203 轮） | `probe["pH"]`/`H_excess` 是**呈现口径**（过了 `_presentation_He` 的幻影碱归零闸）；走步口径是 `probe["pH_solver"]`。F31 实测同一账本两口径 **1.62 vs 12.3803**，据此复算 `S` 会**差 16 个数量级** ⟹ 诊断走步必须**同时取两个口径并注明**，否则整条推断链作废。凡"用探针 pH 复算 S 对不上"先查这里 |
| **嵌套闭包勾不住**（第 203 轮） | `_joint_fire`/`_joint_collect` 等是 `engine.run` 内部的**嵌套闭包**（engine.py L1122/L1155），不是模块属性 ⟹ `setattr(eng, 名字, wrapper)` 只会打 `[缺] … 不存在`，**那是勾子写错、不是引擎缺机制**（第 203 轮据此差点误判"联合步机制不存在"）。走步内部诊断的**唯一**正门是 `judge(..., _probe={})`（`_probe_exit`），它已导出 joint_tries/cycle_jumps/frozen_at/逐候选 S |
| **"诊断工具说数据缺"先怀疑工具**（第 203 轮） | `f31_data.py` v1 因 `ligand=="OH^-"` 过滤条件写错，把 42 条羟合物全滤掉并打印"无 OH⁻ 配合物条目"——**伪装成数据缺失**。`T.beta` 的键是 `center/ligand/nu/logb`、`T.ksp` 用 **`pKsp` 而非 `logK`**、物种名带 PHREEQC 花括号（`Ga^{3+}`）。看到"数据缺"先用一条已知存在的记录**反查过滤器** |
| **别据 S 反推库内常数**（第 203 轮） | 我曾由探针 `S` 反解出"引擎 β₄ = 34.30"，据此宣称"与文献 34.2 相符"，而**库内一直是 37.6**——`S` 里叠着 SIT 离子强度项，反推出的是**有效值**。要核库内常数就**直接读库**（`beta.json`/`ksp.json`），反推值只配当交叉校验且必须显式扣掉 SIT 项。**结论碰巧对，依据全错** = 下一轮会照着错依据去改数据 |
| **`no-cands` 不是缺陷特征**（第 203 轮） | 108/109 例**正常**收敛也走 `exit=no-cands`（含仅 3 迭代就全对的 H48 FeCl₃+3NaOH）。判"同缺陷"必须**组合**判据：固相缺失/极低 ＋ 羟合配合物占溶解金属 >85% ＋ 有 \|S\|>3 的两侧腿被标 `零推进` |
| **一族能过 ≠ 机制正确**（第 203 轮） | 三价金属+强碱 1:3 的 102/109 例"正常"，但它们与失败例**走完全相同的第一步**（`M³⁺+4H₂O→[M(OH)₄]⁻+4H⁺`, ext≈0.75 碱限幅），区别只在**后续能否把固相捞回来**。多数例靠"捞得回来"掩盖了第一步的错误 ⟹ **看着绿的族也要查机制，别把"绿"当成"对"** |
| **`dis_why` 是元组不是字符串** | `dis_why[(key,d)] = (原因, \|S\|, x*, ext_max)`，且原因串带 markdown 粗体（`**零推进（S 强而 x*≈0）**`）⟹ 判据要 `"零推进" in str(...)` **子串匹配**，不能用 `startswith` |
| **跨库核对先用"双库都有的元素"验证换算式**（第 203 轮） | 拿 PHREEQC Thermoddem 核 chemkit 的 Ga 常数时，先把换算式 `logβₙ = n·pKw + log*Kₙ` **在 Al 上验一遍**（两库都有 Al 梯），确认口径无误再去比 Ga。否则"口径错"与"取值分歧"无法区分。**先验证尺子，再量东西** |
| **"库里没有"≠"化学上没有"**（第 203 轮） | PHREEQC 六个主流库（llnl/minteq.v4/wateq4f/phreeqc/sit/pitzer）**全无** Ga 水解配合物（llnl 只有主物种），而 Thermoddem 有完整 Ga 梯 ⟹ 数据库之间的**收录范围**差异极大。**别用"某个库没有"去否定一条化学事实**；要否定得拿文献或另一套完整数据 |
| **库间 pKsp 差 5 个 log 可能是"固相不同"**（第 203 轮） | chemkit `Ga(OH)₃` pKsp −35.1 vs Thermoddem **`GaOOH`** −40.51：差 5.4 个 log 不是谁错，是**无定形三羟化物 vs 晶质羟基氧化物**两种固相。**比对常数前先确认两边说的是不是同一个相**（Al 侧同理：Gibbsite/Boehmite/Gibbsite(am) 三个相并存） |

## 3. 已被实测否掉的方案（别重走，细节见 log）

* 直接删 Kh 通道（⟹ 裸阳离子 pH 7.000、FeCl₃+Cu 族伪造 Cu₂O）——改用显式 β 接管。
* 配对级 `closed_with_ox` 封 H₂O₂→O₂（⟹ KIN06 翻红）——改用方向敏感键。
* 四种"换账本"守卫修 D47（⟹ 都打回 I24）——改修虚拟账本本身。
* 走步侧幻影碱闸（⟹ N20/M01/H42 全崩）——改走"并肩竞争 + 阈值连续化"。
* 只补硫酸根 pKa（⟹ 87 例）／只补二价 β（⟹ 17 例）——先修呈现语义与 pH 帧。
* **抬高 `_buffer_titration` 的 `|He| < 1e-12` 阈值**（悬崖只是被推远）／**把残余强酸/碱折入 Henderson 的 pH**（实测 no-op）——病根是 Henderson 帧漏掉被排除的强酸储备，处置是**弃帧**（交回直读/分支 4）。

## 4. 数据与文献纪律（三条）

1. **`calibrated` 必须写来源与联动**；ΔH 由 thermo 派生时要做**第二条独立自洽核对**。
2. **文献锚优先于引擎输出**（用实测 pH/产量验收，不用"跑出来多少写多少"）。
3. **测试库标准答案可能有错**：先问"这是化学事实，还是某次引擎输出的快照"。
   数据库缺口与引擎缺陷**分开记账**，不许互相掩盖。
4. **物种命名体系要统一到有权威数据的那个**（第 153 轮硅酸族）：NIST/NBS 的 aq
   体系只有 H₄SiO₄，没有"H₂SiO₃(aq)"独立条目 ⟹ 库内保留旧标签但写 H₄SiO₄
   体系换算值，并留下警戒注记（`H_2SiO_3` = **−1468.6**，**不是**教科书固体
   偏硅酸的 −1189；改名前要同时改 pKa/beta/用例三处）。

## 5. 每轮固定动作（清单）

1. **建/更新 todo**：本轮子任务 + 路线图；轮内更新，**轮末刷新**（硬性要求）。
2. 先测量、再动手；一次只改一个点；数据改动走 `dev.py patch`。
