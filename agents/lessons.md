## 1. 缺陷类别（最常犯的十类，括号内是"回忆触发"）

| # | 一句话 | 回忆触发 | 详见 |
|---|---|---|---|
| D1 | **删掉一个近似而不给替代 = 造空洞**；要用更好的数据接管 | "这个近似不准，删了它" | X-32 capstone |
| D2 | **口径不一致**：pick 与 solver 在**不同的态**上评同一个 S | `零推进`、残差比同族高一个量级、"挑得起走不动"、**同一个数在阈值两侧跳变** | X-8 / X-43 |
| D3 | **近似掩盖问题**：把"饱和溶液 pH""定量滴定""丢弃残余"当成真值 | 任何"用简化常数/公式代替真平衡"处 | X-32 / X-43 |
| D4 | **死数据**：注了却没被消费 | 改完数据"没反应" | Co(OH)₃ 例外表 |
| D5 | **阈值边缘当化学**：`changed`/`degree`/显著线被写进标准 | 差百分之几就翻红 | 多例（见 log） |
| D6 | **配对级判据表达不了方向** | 给 redox 加限制时 | X-38 族 / slow_as_red_with |
| D7 | **机制加了但没接线**：快路径/缓存/预组装绕过新规则 | 改完"逐位不变" | slow_as_red_with / is_dyn |
| D8 | **全局修复打坏既有体系** ⟹ 先测量爆炸半径，再想更窄判据 | 想"全局统一"修一处 | 幻影碱闸三度被否 |
| D9 | **数据库有限性掩盖引擎问题**（反之亦然）：两者**分开记账** | 标准与引擎不一致时 | 硫酸根 / 二价 β |
| D10 | **把有意设计当缺口**：动数据前先读该条目自己的 note | 看到"缺一条数据" | Zn²⁺/Zn 的 h2_passivation |

## 2. 工具与编码坑（每轮都可能踩）

| 坑 | 一句话做法 |
|---|---|
| JSON 里写 ASCII 引号 | 用中文引号 `“”`，或转义 |
| Python 三引号尾部 `""""` | 新串以 `"` 收尾时，**终止三引号另起一行** |
| 补丁锚串过期（上一轮改/回退过） | 改补丁前先 `read` 当前文本；或先跑**内存复现探针** |
| `patch --check` 不校验 JSON | 落盘后立即复验；先在内存里 `json.loads` 一遍 |
| 补丁没落盘就跑套件 | 先看输出有没有 `[写入]`，再决定跑不跑 |
| 生成端截断输出 | **一次运行全量结构化留档**（`.tmp_dev_results.json`），后续用 `tools/readback.py` 读 |
| PowerShell 管道重写源文件 | 中文会变乱码 ⟹ 只用 `write`/`edit` 工具 |
| `git commit -m "…中文引号…"` | 写消息文件，`git commit -F` |
| 工具名与 stdlib 同名 | `tools/` 会成为 `sys.path[0]` ⟹ 禁止 `inspect.py`/`json.py` 这类名字 |
| 探针里用 `__file__` | `dev.py patch` 的 exec 环境没有它；spec 只放 `PATCHES` |
| 控制台 GBK | 脚本走 `dev.py run`；控制台只打 ASCII |

## 3. 已被实测否掉的方案（别重走，细节见 log）

* 直接删 Kh 通道（⟹ 裸阳离子 pH 7.000、FeCl₃+Cu 族伪造 Cu₂O）——改用显式 β 接管。
* 配对级 `closed_with_ox` 封 H₂O₂→O₂（⟹ KIN06 翻红）——改用方向敏感键。
* 四种"换账本"守卫修 D47（⟹ 都打回 I24）——改修虚拟账本本身。
* 走步侧幻影碱闸（⟹ N20/M01/H42 全崩）——改走"并肩竞争 + 阈值连续化"。
* 只补硫酸根 pKa（⟹ 87 例）／只补二价 β（⟹ 17 例）——先修呈现语义与 pH 帧。

## 4. 数据与文献纪律（三条）

1. **`calibrated` 必须写来源与联动**；ΔH 由 thermo 派生时要做**第二条独立自洽核对**。
2. **文献锚优先于引擎输出**（用实测 pH/产量验收，不用"跑出来多少写多少"）。
3. **测试库标准答案可能有错**：先问"这是化学事实，还是某次引擎输出的快照"。
   数据库缺口与引擎缺陷**分开记账**，不许互相掩盖。

## 5. 每轮固定动作（清单）

1. **建/更新 todo**：本轮子任务 + 路线图；轮内更新，**轮末刷新**（硬性要求）。
2. 先测量、再动手；一次只改一个点；数据改动走 `dev.py patch`。
3. **按分层协议选测试层级**（见 [`tools.md`](tools.md)）：T0 不跑 / T1 定向 / T2 全量锚定 /
   T3 双约定 + perf + 审计（仅在落盘前）。**默认 T1**，跑全量前先问"改动范围真的这么宽吗"。
4. 落盘后先复验，再按层级跑；**一次运行全量留档**，后续用工具读，不靠重跑换信息。
5. 入档：`log.md` 加本轮小节（现象 + 实测数字 + 结论 + 待办），提交，汇报指标
   （套件双约定、iters/sof、resid p50/p90/max、n(|S|>1)、n(|S|>0.1)、逐例化学增量）。
6. **本轮若踩到新坑或否掉一个方案，立刻往本文件加一行**；细节写进 log。
