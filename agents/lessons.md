## 1. 缺陷类别（最常犯，括号内是"回忆触发"）

| # | 一句话 | 回忆触发 |
|---|---|---|
| D1 | **删掉一个近似而不给替代 = 造空洞**；要用更好的数据接管 | "这个近似不准，删了它" |
| D2 | **口径不一致**：pick 与 solver 在**不同的态**上评同一个 S | `零推进`、"挑得起走不动"、同一数在阈值两侧跳变 |
| D3 | **近似掩盖问题**：把"饱和溶液 pH""定量滴定""丢弃残余"当真值 | 任何"用简化常数/公式代替真平衡"处 |
| D4 | **死数据**：注了却没被消费 | 改完数据"没反应" |
| D5 | **阈值边缘当化学**：`changed`/`degree`/显著线被写进标准 | 差百分之几就翻红 |
| D6 | **配对级判据表达不了方向** | 给 redox 加限制时 |
| D7 | **机制加了但没接线**：快路径/缓存/预组装绕过新规则 | 改完"逐位不变" |
| D8 | **全局修复打坏既有体系** ⟹ **先测爆炸半径，再想更窄判据** | 想"全局统一"修一处 |
| D9 | **数据库有限性掩盖引擎问题**（反之亦然）：两者**分开记账** | 标准与引擎不一致时 |
| D10 | **把有意设计当缺口**：动数据前先读该条目自己的 `note` | 看到"缺一条数据" |
| D11 | **兜底吞原因**：`except: reason="模块异常"` 让缺口与缺陷都看不见；**判别与求和必须同一集合** | 看到"某模块异常/降级" |
| D12 | **近似帧与被它排除的物种静默不一致**：判据用**自洽性**（"该物种在这个 pH 下能否存在"），别用"存在/量够" | 近似值偏离直读好几个单位 |
| D13 | **同一个量被两套记账法各记一遍**，在 `max`/比较处竞争 ⟹ pH 一级跳变。判据要认**来源**，不能只比数值大小 | 同一账本两次评估给截然不同的值 |
| D14 | **判定类开关在 `f(x)` 内逐点评估 = 接缝悬崖**：修法 = **双端一致冻结**（步首与 `x_max` 端都 adopt 才整步 ON）。**按步型下判据即曲线拟合，不可做** | 走步停在中途、`x_bis` 恰在某判据边界上 |
| D15 | **接缝/补丁可能正被标准隐性依赖**：消灭悬崖后翻红的用例，先问"它的 PASS 是不是靠接缝落点"——若是，暴露的是**真实缺陷**，另行记账修根源，不为它保留接缝 | 修完接缝/口径后个别例"莫名"翻红 |

## 2. 方法与判断纪律（**最关键**，动手前必扫）

| 一句话 | 含义 |
|---|---|
| **一切以化学事实为准** | 不用指标不治本的小补丁；测试标准与化学事实冲突时先问"这是事实还是旧引擎快照" |
| **先验证尺子，再量东西** | 新写的探针/检测器必须用**判据已知**的用例校准（正对照 + 负对照）才有资格用于普查。没校准的检测器会把 PASS 例报得比 FAIL 例还糟 |
| **先测量，再动手** | 一次只改一个点；改动前先量全量、再按**实测命中点**收紧（两次全量比事后猜便宜） |
| **改闸/守卫前先枚举"新放行集合"并逐例核对** | "判据看起来更对" ≠ "改动更安全"。把 delta 集合列出来看，别只看逻辑漂亮 |
| **先做反例预测** | 判据写完先问"**已知的哪一族会落在同一条判据里**"。守卫类判据两版都被否 = 方向需换，不是继续调参 |
| **别把尺子挪到问题变小** | 放大容差去盖住悬崖 ⟹ 打红别的体系。修法要能**区分来源** |
| **"精确解返回 None"先问"解不出"还是"被闸挡"** | None ≠ 无解。查清是哪条 `return None` 挡的（把判据字段打出来），**只看包装层永远发现不了** |
| **报"被某闸挡住"要打出判据字段** | 一个闸常有多条判据，只记一条会误判修法面 |
| **有固相时"β 比值被违反"是合法的** | 固相在场时游离金属被 **Ksp** 钉住而非被 β 钉住 ⟹ 任何"用 β 检验终态自洽"的判据**必须先排除有固相的用例** |
| **看着绿的族也要查机制** | 一族"正常"可能只因碰巧没触发缺陷（如"后续能捞回来"掩盖了第一步的错误）。**别把"绿"当成"对"** |
| **`no-cands` 不是缺陷特征** | 正常收敛也走它。判"同缺陷"要用**组合**判据 |
| **成熟程序先看它的"未知量集合"** | 读 PHREEQC 源码比读文献有用：它把 pH 当**未知量**、电荷平衡当**残差方程**一起 Newton 迭代。若我们的量是"由两个输入算出的分支"而成熟程序是"由守恒方程解出的唯一解"，那是**设计差异** |
| **先用"两边都有的东西"验证换算口径** | 跨库核对常数时，先在**两库都有数据**的元素上验换算公式，再去比只有单侧数据的元素。否则"口径错"与"取值分歧"分不开 |
| **库间常数差异先问"是不是同一个相/同一个量"** | pKsp 差 5 个 log 可能是"无定形 vs 晶质"；"库里没有"≠"化学上没有"（各库收录范围差异极大） |
| **条件常数 ≠ 标准态常数** | 本库 β 一律 **I→0**。文献给条件值时先换算或要 I→0 值；**逐级 K 与累积 β 不可混**（累积可小于逐级） |
| **写 assert 前先手算一个例子** | 否则会自己把自己拦下并误以为数据错 |
| **"账本欠定"会让电荷自洽 pH 变成垃圾** | 引擎把未解离的强酸（`H₂SeO₄` 0.5 mol）按**中性分子**记账 ⟹ Σz·n 看起来"不平衡"，而那个不平衡是**账本自己的缺口**，不是 pH 错。判"pH 读错"前必须确认账本里**没有未解离的酸/碱储备**能解释该缺口 |
| **"引擎自认未达平衡"是最可靠的内生判据** | `max_abs_S`（探针）大 ⟹ 引擎自己承认残差大，此时它的 pH 才可疑。实测：4 例候选里 3 例 `max_abs_S = 0.0` 且套件 **PASS**（只是账本欠定），只有 F31 `max_abs_S = 13.305` 且 FAIL。**优先用引擎自己的残差量筛，而不是外部推断的"应该 pH 多少"** |
| **并行 worker 数按「物理核」定，不按逻辑核取满** | 第 207 轮实测（i7-8650U = 4 物理核 / 8 逻辑核）：墙钟 2w 74.8s / 4w 55.5s / **6w 50.0s** / **8w 51.5s** ⟹ **8 不快于 6**，超订物理核只增争用（单例 CPU 成本 111ms→220ms，CPU 合计 130s→258s）。收益在 4~6 饱和。默认取 `min(4, 逻辑核//2)`，要榨最后 ~10% 再手动 `--jobs=6` |
| **自己建进程池的脚本必须有 `if __name__ == "__main__":`** | Windows 只有 `spawn`，子进程会**重新 import 本模块**；脚本主体若在模块顶层执行，子进程会再次建池 ⟹ 递归派生 ⟹ `BrokenProcessPool`。库函数（如 `testsuit`）自身无此问题，**只有"脚本自己建池"才要加护板** |
| **跑一次，读多次——绝不为"换个角度看同一批数据"而重跑** | 这是本仓最容易犯的低效（第 206 轮我在同一轮内重跑套件 **3 次**，只为分别看：结果、耗时榜、并行墙钟）。正确做法：**一次运行把全部面向写进一个 JSON**（逐例 ok/errors/ms + 慢例榜 + 失败清单 + 汇总），之后用读取器看任何切片。`tools/suite_parallel.py` 写 `logs/suite-parallel-latest.json`，`tools/suite_show.py {summary\|fails\|slow N\|case <前缀>\|diff <另一份>}` 负责读。**改代码前跑一次存档，改完再跑一次，中间一律读档。** |
| **"最慢用例"榜先排除冷启动，再谈算法病态** | 第 206 轮实测：套件里最慢的十例全是 `1 HCl+NaOH`、`3 HCl+NaOH(碱过量)` 这类**教科书中和**，看着像算法病态；实际是**每个 worker 的首个用例独自承担全部惰性缓存构建**——同一用例在预热过的进程里只要 9~270 ms。加一行预热后 **CPU 合计 446s→314s**，那十例全部离开慢例榜。**并行器必须照抄串行路径的预热**，否则既慢又污染画像 |
| **"公式对" ≠ "改动有效"——先做因果模拟** | 第 207 轮：`fixsim`（monkey-patch 先验因果）证明"改 pH 接线"修不好 F31，省下一次白改。第 208 轮：修分支 4 的弱酸式（**化学上确实错**：`h²+Ka·h−Ka·c=0` 只对纯弱酸成立，而账本里共轭碱 0.7431 与酸 0.2534 共存）——实测 pH 反而由 1.62 变 **0.55**、`max\|S\|` 13.3→17.5，**更差**，遂回退。**判据：改完必须先看"末态是否更接近平衡"，而不是看"公式是否更正确"。** |
| **"无步可走"要先分清是「候选没了」还是「候选被选中但 x\*=0」** | F31 实测：`exit=no-cands` 很容易被读成"候选耗尽"，但逐迭代轨迹（`CHEM_TRACE=1`）显示**沉淀腿被正确挑中、S=+28.3、pH 也对**，是 `solve_extent` 返回 `x*=0` ⟹ 零推进 ⟹ 退出。**要区分"退出判据/候选筛选"与"求根失败"，只有逐迭代 trace 能分开**；只看终态探针会一直找错方向 |
| **二分起点上的双模态 = 假"无根"** | 在 `solve_extent` 的起点手工扫 `S_of(x)`：`x=0` 时 `estimate_pH` 取酸侧给 **1.620**（S=−3.97），挪动 **1e-6** 就翻到碱侧 **5.764**（S=+8.46）。⟹ 二分从 `f(0)<0` 起手，按"括号内无过零"返回 0。**判据：若同一 (ledger, He) 在 1e-6 级扰动下 pH 跳好几个单位，则任何"求根"都建立在流沙上**——先修不连续，再谈求根 |
| **"引擎自认未达平衡"是最省事的判别器** | 想用某个窄条件放行精确解时，先看 `max_abs_S`（自认残差）。第 210 轮实测：条件`无 pKa 族 ∧ 无固相 ∧ \|ΔpH\|>1` 命中 **68 例（51 例 PASS）**——太宽不能用；**再加 `max_abs_S > 3` 就只剩 1 例（F31）**。因为另外 67 例 `max_abs_S = 0.0`：引擎自认已平衡，那个 Δ 只是建模差异，**不该动**。**判据优先用引擎自己的残差，而不是外部推断的"应该 pH 多少"** |
| **窄条件的爆破半径要逐级量化，不能只看"看起来合理"** | 同一个想法分四级量：只加"无 pKa 族" → **640 例**（563 PASS，占全库 55%，不可用）；∧无固相 → 281；∧\|Δ\|>1 → 68；∧残差>3 → **1**。**"逻辑上更对"的条件可能命中过半用例**；必须把每一级的命中数与其中 PASS 数都打出来 |
| **推翻旧结论时旧结论直接删掉** | 它不是历史，是错的。只在本文留一行"已否掉" |

## 3. 工具与编码坑（每轮都可能踩）

| 坑 | 做法 |
|---|---|
| JSON 里写 ASCII 引号 / 三引号尾部 `""""` | 用中文引号；终止三引号另起一行 |
| 补丁锚串过期 | 改前先 `read` 当前文本；或先跑内存复现探针 |
| 落盘不校验 / 没落盘就跑套件 | 先在内存 `json.loads` 一遍；看输出有没有 `[写入]` |
| 输出被截断 | **一次运行全量结构化留档**（`dev.py` 自动写 `logs/`），后续用 `tools/readback.py` 读 |
| 改数据用文本锚串 | 改用 `tools/jsondb.py` **按键路径**改 |
| PowerShell 管道重写源文件 / `>` 重定向 | 中文会乱码、重定向写 UTF-16（首字节 `FF FE` 直接崩）⟹ 只用 `write`/`edit` 工具，留档靠 `dev.py` |
| 编码异常静默混入（BOM/UTF-16/NUL） | `dev.py hygiene --fix` 就地重写为无 BOM UTF-8 |
| `git commit -m "…中文引号…"` | 写消息文件，`git commit -F` |
| 工具名与 stdlib 同名 | `tools/` 是 `sys.path[0]` ⟹ 禁止 `inspect.py`/`json.py` 这类名字 |
| 探针里用 `__file__` | `dev.py patch` 的 exec 环境没有它 |
| 控制台 GBK / 管道要等进程退出 | 脚本走 `dev.py run`；控制台只打 ASCII；别管道，事后读 `logs/` |
| **手工猜诊断参数** | `(ledger, He)` 必须**取自真实运行**（`CHEM_TRACE=1` 的 `[micro]`/`[micro-led]` 行）；猜参数会诊到走步根本没经过的态 |
| **临时探针** | 别把函数体复制进探针（真文件可 `git checkout --` 回退）；A/B 要在**同一进程换函数引用**，末尾断言已还原 |
| **模块级补丁打不动热路径** | `engine.py` 对 `estimate_pH`/`estimate_state`/`_buffer_titration`/`_solve_ph` 是**按名导入** ⟹ 改 `speciation.<名>` 对**走步无效**（只有模块内自调用受影响），探针会跑出**假阴性**。要么打引擎真正调用的引用，要么直接改真文件 |
| **嵌套闭包勾不住** | `engine.run` 内部的闭包不是模块属性 ⟹ `setattr(eng, 名, wrapper)` 只会打"不存在"。走步内部诊断的**唯一正门是 `judge(..., _probe={})`** |
| **`probe["pH"]`/`H_excess` 是呈现口径，不是走步口径** | 呈现层会把 He 归零 ⟹ 用探针值做算术会得出"账本不平"的错误结论。要拿走步口径只能**逐步回放** |
| **`dis_why` 是元组带 markdown 粗体** | 判据用**子串匹配**，不能用 `startswith` |
| **回退到已知状态不要重测** | 结果已知（git 快照 + 留档），重跑纯浪费 |
| **诊断工具说"数据缺"先怀疑工具** | 过滤条件写错会**伪装成数据缺失**。先用一条已知存在的记录反查过滤器（注意 `T.beta` 的键名、`T.ksp` 用 `pKsp`、物种名带花括号） |
| **别据 S 反推库内常数** | `S` 里叠着 SIT 项，反推出的是**有效值**。要核常数就**直接读库**；反推值只配当交叉校验且必须显式扣掉 SIT |
| **量"分歧"前先对齐被测函数的参数契约** | 少传一个参数（如 `c_H`）能把 9 例分歧变成 349 例 ⟹ 分歧报告必须写明"用了哪些参数" |
| **审计/测量类子代理运行期间冻结被读目录** | 并行编辑会让它读到变动中的树，结论作废 |
| **子代理产物要指定落盘路径** | 写进 `tools/<name>.py` + `logs/<name>.json`，它被中断成果仍在 |
| **上下文压缩后** | 规范文件（本文件 + `discipline.md` + `tools.md`）**重读再动手**——摘要是索引，不是规范 |

## 4. 数据与文献纪律

1. **`calibrated` 必须写来源与联动**；ΔH 由 thermo 派生时要做**第二条独立自洽核对**。
2. **文献锚优先于引擎输出**（用实测 pH/产量验收，不用"跑出来多少写多少"）。
3. **记忆值不得当已核数据**：查不到出处就**不入库**（宁缺勿错），或写
   `calibrated: provenance 未核实` 并单列待复核。
4. **测试库标准答案可能有错**：先问"这是化学事实，还是某次引擎输出的快照"。
   数据库缺口与引擎缺陷**分开记账**，不许互相掩盖。
5. **数据与标准冲突时不自行裁决**：把两侧证据一并摆给使用者（引擎值 vs 标准值 +
   解析核对），由使用者定"改数据"还是"重裁标准"。**两套 pKw 约定同时打红同一批
   ⟹ 是取值冲突，不是约定/引擎缺陷。**
6. **物种命名统一到有权威数据的那个体系**，库内可保留旧标签但写换算值并留警戒注记。

## 5. 已被实测否掉的方案（别重走，细节见 log）

* 直接删 Kh 通道（⟹ 裸阳离子 pH 7.000、伪造 Cu₂O）——改用显式 β 接管。
* 配对级 `closed_with_ox` 封 H₂O₂→O₂（⟹ KIN06 翻红）——改用方向敏感键。
* 四种"换账本"守卫修 D47（⟹ 都打回 I24）——改修虚拟账本本身。
* 走步侧幻影碱闸（⟹ N20/M01/H42 全崩）——改走"并肩竞争 + 阈值连续化"。
* 只补硫酸根 pKa（⟹ 87 例）／只补二价 β（⟹ 17 例）——先修呈现语义与 pH 帧。
* **抬高 `_buffer_titration` 的 `|He|` 阈值**（悬崖只是被推远）／**把残余强酸/碱折入
  Henderson**（实测 no-op）——病根是帧漏掉被排除的强酸储备，处置是**弃帧**。
* **整体放宽 pH 精确解的 B3 闸**（⟹ 新放行 47 例中 24 例会变、13 例动 >1 pH 单位）。
* **`charge_pH` 全局接管 pH**（⟹ 全库 156 例差 >1，且多数引擎是对的——它把总量当溶解量）。
* **全局换联立闭合行**（⟹ 移动 14.6% 的联立调用）。
* **给非-redox 加酸碱预算闸**（实测预算**已生效**，配体腿被正确封顶——不是病根）。

## 6. 每轮固定动作

1. **建/更新 todo**：轮内**实时**标记完成，轮末刷新（硬性）。
2. 先测量、再动手；一次只改一个点；数据改动走 `dev.py patch` / `tools/jsondb.py`。
3. **按分层协议选测试层级**（`tools.md`）：T0 不跑 / T1 定向 / T2 全量锚定 /
   T3 双约定 + perf + 审计（仅落盘前）。**默认 T1**；先问"改动范围真的这么宽吗"。
4. 落盘后先复验，再按层级跑；**一次运行全量留档**，不靠重跑换信息。
5. **入档三分法**（使用者要求）：
   | 内容 | 去处 |
   |---|---|
   | 当前状态、指标、下一步、活台账 | `handoff.md`（**覆盖写**，不留历史节、不留旧版本） |
   | 已证伪假设、"别重试"教训、方法纪律 | **本文件** |
   | 本轮过程、实测数字、推导链 | `log.md`（按轮编号） |
6. 提交并汇报指标（套件双约定、iters/sof、resid p50/p90/max、n(\|S\|>1)、
   n(\|S\|>0.1)、逐例化学增量）。
7. 踩到新坑或否掉方案时，**同时**往本文件加一行、往 `handoff.md` §3.2 加一条。
