## ⑪ 方法教训（对应 `lessons.md` 新增条目）

1. **物种活度是状态量，不能按"写在箭头哪一侧"分派标准态**（D17）。改 `plan` 的
   `typ` 或任一 `typ` 分支的公式后，**第一件事是把代表性反应两个书写向都枚举、
   核对 `S` 反对称** —— 比跑全量便宜，且能直接抓住这类缺陷。
2. **"下限/回退"类常数先拆定义式验量纲**（D18）：`A_GAS = 1.0/101.325` 一眼是
   **分压比**。凡见"同一常数既作回退值又作钳位限"，先各写一遍它的定义式。
3. **任何"压住驱动"的数值约定都在替缺失的化学注解干活**：拆掉 `A_GAS` 后，
   **同一轮内**立刻翻出两类被它掩盖的缺口（`Sn11` 缺动力学注解、`Y09` 收敛未走完）。
   移除这类约定前要**预测会翻出哪些注解缺口并预留工作量** —— 把翻红当回退理由是错的。
4. **判别锚 ≠ 化学护栏**：`GS5` 是判别锚（有修/无修翻转），`Y09` 的 `has_not` 是
   护栏（两边都过、只防退化）。**写 DB 注与 handoff 时必须标明是哪一种**，
   不能拿护栏充判别证据。
5. **性能数字要做"同用例对照"**：`chemkit.testsuit perf` 比的是**受控基线**（上次刷新的用例集），
   用例一变就会把 `n` 这类纯规模量混进"位移"清单，且分不清"用例变多"与"引擎变慢"。
   本轮靠 `chemkit/helper/perf_diff.py` 把 `+24%` 墙钟**精确定位到单例** `EU01`。
6. **测试库改动用 `--check` 先验证再 `--write`**，且新锚要**独立于引擎可推**
   （本轮 `pH = pKa` 与 `Ksp/(Ka1·Ka2)` 两条都是手算可得的判据）。

## ⑧ 方法教训

1. **ε 属于平衡，不属于候选表示**（D21）：同一反应的所有候选构造路径
   必须携带**同一组**修正参数；新加候选生成路径时，对照既有路径的

   无旁观者时两者恰好相等。

   上一提交跑一次定向子集，把"本轮引入"与"上轮既有"分开（本轮 EU01
   resid_max 位移即上轮既有，5 分钟排除）。

# 第 292 轮（接手续做）· 高阶氯络合物族结案：`ZN6` 断言键 + PbCl₂ 族 5 例重裁

## ② `ZN6`：诊断链（**结论：用例 bug，引擎无罪**）

1. `chemkit.testsuit case ZN6` ⟹ `degree=0 changed=False reacted=False`，但**账本净差**写着
   `0.24583Cl^- + 0.089491Zn^{2+} -> 0.0721183[ZnCl_3]^- + 0.0121036[ZnCl_2]
   + 0.0052677[ZnCl]^+ + 1.39e-06[Zn(OH)]^+` —— **账本完全正确**（72% 三氯主导，
   与库值独立不动点推导一致）；失败信息却是 `[ZnCl_3]^- 产量 0 < 0.05`。
2. 新工具 `chemkit/helper/specdist.py`（**三层并列**：账本 / 净差 / 呈现）⟹ 呈现层
   `production` 里明明有 `[ZnCl_3]^- = 0.072118`、`final` 里也有 ⟹ **不是呈现层丢的**。
3. 读 `testsuit.py` 第 258–276 行：`has` 读 **`amt`（池口径）**，池成员（`pool_map`）
   被**聚合到锚上、物种名下恒 0**；`has_not`/`has_range` 才读 **`amt_sp`（物种级）**。
   `T.pool_ligands = {Cu²⁺: [Cl⁻], Sn²⁺: [Cl⁻], Zn²⁺: [Cl⁻]}` —— **Cd²⁺ 不在池里**，
   这就是 `CD3` 用同一个 `has` 键能过、`ZN6` 恒 0 的全部原因。⟹ 新缺陷类 **D22**。
4. 修法：`has` → `has_range`（物种级区间）`{[ZnCl_3]^-: [0.05,0.12],
   [ZnCl_2]: [0.004,0.03], Zn^{2+}: [0.004,0.02]}` ⟹ 通过。

### 二、**根因**：`JOINT_TOL` 与 `FREEZE_MAX_S` 之间的"容差带"制造活锁

`joint_tries ≈ joint_ok ≈ freeze_events ≈ revive ≈ 1000`、`micro_steps ≈ 2100`。

⟹ `_try_revive` 判"仍强驱动"解冻 ⟹ 再联立 ⟹ **活锁**。

并加**步长判据**（`JOINT_DX_MIN = 1e-6`）：平衡的数学定义是"`F = 0` **且 x 不再变**"，
只判残差是半个判据。实测：

|---|---|---|---|---|
| TOL=0.05（原）| 3002 | 3053 | 487 | 35604 iters / 1280 通过 |
| TOL=0.01 | 3002 | **154** | 413 | **30406 iters(−14.6%) / 1283(+3)** |

## 第 298 轮：`15 CaCO3+HCl` 活锁的完整机理链（全部由实测确立）+ 三次改坏全库的教训

### 一、本轮确立的**硬事实**（每一条都有实测输出，非推理）
1. **`S_of` 对互逆反应的 S 不反号**（`15` 的 `CO₂/HCO₃⁻` 对）：
   中间态 `CO₂ = 0.99865 > 泡点 0.034442` 时
   `CO₂+H₂O→HCO₃⁻+H⁺` 的 `S = +1.462891`、`HCO₃⁻+H⁺→CO₂+H₂O` 的 `S = +0.000000`
   ⟹ **和 = +1.4629 ≠ 0**（不变量破坏）。这就是 996 次来回的数学根源。
2. **成因定位到 `plan` 的 `typ` 编码**：`typ=4`（气体分支）**只在 `c.pr` 循环里赋值**
   ⟹ 同一 `CO₂` 作产物走 `min(c_g, H·p)`、作反应物走真实浓度。
3. **活锁的实际步序列**（`_exec` 打点）：
   `it=10 CO₂+H₂O→HCO₃⁻+H⁺ ext=0.00130423 S=+1.463`
   `it=11 HCO₃⁻+H⁺→CO₂+H₂O ext=0.00130423 S=+1.462`（**ext 逐位相同**）
   ⟹ 落实后 `HCO₃⁻ = 0.0013221799`，下轮起点又回到 `4.6587759e-05`（**逐位相同**）。
4. **扫气从未运行**：`_sweep_gases` 只在 `for _sweep_round` 循环末尾（`for it` 之后），
   而 `15` 的 `for it` 因活锁永不退出 ⟹ 3002 次迭代里扫气打点 **0 次**，
   而 `CO₂ > 泡点` 的打点 **2999/3006**。
5. **反应物侧的气体必须用真实浓度**（三次实验的反证）：把气体封顶推广到反应物侧
   ⟹ 凭空抹掉 96% 的反应物 ⟹ 全库 **−506 ~ −510 例**（`NH₃` 不逸出、
   `H₂S` 不沉 ZnS、pH 全变碱）。**`min(c_g, H·p)` 只对"可逸出的那一份"成立，
   而账上超泡点的存量是尚未扫气的真实溶解量。**

### 二、**三次改坏全库**的完整教训（本轮最重要的产出）

|---|---|---|---|

| 3 | 修 `logQ` 符号（`+side·ν·v` → `−side·ν·v`） | 777/1378（**−506**）| 同上，符号只是次要错误 |

### 五、第 4 次尝试（循环内扫气）的否证 —— **化学上错，不是断言该重裁**
方向：把 `_sweep_gases` 从 `for it` 之后**移入循环内**，使账本不再长期持有超泡点气体。
实测：**iters −21.4%（30406 → 23896）**，但翻红 11 例
（`T11/T12/H35/H89/W17/Y02/Y04/Y22/Z36/N06/CH3`），且**症状一致地违背化学**：
* `H89 Ca(HCO₃)₂+Ca(OH)₂`（pH 12.37）逸出 **`CO₂` 0.930 mol**
* `T12 NaHCO₃+过量Ca(OH)₂`（**pH 14.0**）逸出 **`CO₂` 0.430 mol**
* `Y02 Pb(NO₃)₂+Na₂S`（pH 9.25）逸出 **`H₂S` 0.244 mol**

**强碱体系逸出 `CO₂`、pH 9.25 逸出 `H₂S` —— 化学上不可能**。
根因：循环开头那一刻的账本是**走步中间态**，`CO₂` 尚未与碱完成质子转移就被判
"超泡点"扫走，等于把"即将变成 `CO₃²⁻` 的碳"当成逸出的 `CO₂`。**这正是
`_sweep_gases` 原本放在"不动点收敛后"的原因**（其注释即写明 Le Chatelier 语义）。
⟹ **正确修法不是"在循环内扫气"，而是"让 `for it` 能退出"**，即解决活锁本身。
已回退，基线恢复 **1283/1378**。

## F. 化学事实裁决：`E01` 的哪个答案是对的？

`E01` 投料 `SO_2 1 mol + H_2S 2 mol` 于 **1 L** 水。
· 溶解 H₂S 的泡点 = `H·p_ext = 0.1013 M` ⟹ 1 L 里**最多溶 0.1013 mol**。
· 投 2 mol ⟹ **约 1.9 mol 必然逸出**（这正是 H₂S 刺鼻气味与毒性的来历）。
· 所以**开放模式的 S=0.498 是物理正确的**；闭合模式的 S=3.0 是
  「把 2 mol H₂S 全当溶解态」的**非物理**结果。

但用例断言要求 `S ≥ 2.7`（`eq = 2H_2S + SO_2 -> 3S + 2H_2O`，`degree=complete`）
—— **该断言建立在"气体不限泡点"的旧语义上**。按纪律「标准答案可能有错：
先判化学事实 vs 某次引擎输出的快照」，这属于**断言需重裁**，不是引擎缺陷。

⚠️ 但要注意断言背后的**化学意图是对的**：Claus 归中反应**确实**要发生。
真实情形是「**持续通入** H₂S/ SO₂ 气流」——储库不断补充，反应持续推进，
最终 S 产量由**通入总量**决定。本引擎的静态投料模型下，等价表述是：
**气相储库耗尽的量仍应全部参与反应**（气相的 1.9 mol H₂S 不是"消失"，
而是"暂存"，最终应被归中消耗）。

⟹ 这正是下一轮要实现的语义：**气相是暂存，不是终点**；反应应能一直
从气相抽取，直到气相耗尽或驱动为零。当前 301d 只抽到泡点差就停（
`steps_n=14` 全微步、`exit=no-cands`），需让 `gas` 类候选的推进不受
泡点差限幅，而受**气相存量**与**驱动**限幅。

### K.1 实测：到底是哪对电对生成了问题反应

问题反应 `S + SO_2 + 2H_2O -> H_2S + SO_4^{2-} + 2H^+`（`E01` 实际执行的）：


**S 在这里是 `a.ox`（氧化剂）**，不是还原剂！

# 第 302 轮：气体模型 —— 先用实测钉死不对称所在

## A. 决定性实测：投料气体**违反泡点**，自产气体**遵守泡点**

`_scratch/measure_asym.py`（基线 `73ad0cf`，`c_sat(H_2S) = 0.1013 M`）：

| 情形 | 账本溶解量 | 判定 |
|---|---|---|
| 投料 `H_2S` 2 mol（不反应） | **1.99955** | **违反 c_sat**（超 19.7 倍） |
| 投料 `H_2S` 0.05 mol | 0.04993 | 正确（未饱和） |
| 自产 `H_2`（Zn+HCl） | 0.00079 | 正确（余 0.49921 进气相） |

⟹ 同一物种在账本里的"可溶上限"取决于**它是投料来的还是反应产来的**，
这就是 `E01` 靠"违反泡点、一步走完 Claus"通过、而基准却显示 S=3.0 的机制。
**这是不对称的根源，也是下一轮要消灭的对象。**

## B. 由此得到的正确语义（**不是推理，是上面那张表的直接读数**）

* 投料气体：也应遵守泡点 ⟹ 超泡点部分进**气相**；
* 自产气体：同上（已经这样做）；
* **气相必须能回溶供料**：水相消耗即从气相补充，而不是只补到"泡点差"
  （301d 的真缺陷：投料全进气相后水相无反应物，E01 production 为空）。

对称性（与固相逐条对应）：
```
固相：投料 CaCO3(s) 入账 + dissolve 候选溶解       + 活度 1
气相：投料 X(g)      入账 + 相转移候选回溶          + 活度 p_ext/p°
```
