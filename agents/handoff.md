## 1. 已查清的核心结论（**读这节可省数十轮**）

### 1.1 ⭐ B+C（29 例 / 216.6 残差 / 占全库 66%）卡在**表示层不自洽**，该轴已收束

**八次尝试全部实测否决**，最后用**独立于引擎的鲁棒优化器**判定为**「无解」**：

| # | 尝试 | 结果 |
|---|---|---|
| 1 | 换 `joint` 闭合行为守恒方程（`charge_pH`）| 净持平（8/1147 变动，0 翻转）|
| 2 | 降低联立触发门槛（`it>=64` → 8）| 净负（1029/1176，`F14` 破）|
| 3 | `solve_extent` 端点一致性检查 | 无效（前提本身错了：`f(0)` 为**正**）|
| 4 | 修分支 4 弱酸式（加共轭碱）| **更差**（pH 0.55）|
| 5 | 收紧 `exact_proton_pH` 的 B3 闸 | 24/47 例变动 |
| 6 | 全局 `charge_pH` 接管 | 156 例差 >1，多数是引擎对 |
| 7 | 给足迭代（×14）| 残差**逐位不变**（11.9427）⟹ 非欠迭代 |
| 8 | **Nelder-Mead 求最小残差**（无 Jacobian）| **max\|F\|=4.58 ⟹ 无解** |
| ✅ | **停滞期联立触发**（走步层，非联立层）| **唯一正收益**，已转正 |

**决定性证据**（`tools/solvability.py`，`H45`）：无 Jacobian 的鲁棒优化器把
8 方程 / 8 变量系统的最小最大残差压到 **4.58** 就到底，其中
**连 pH 闭合行本身都不可满足**（`F[7] = −4.58`）⟹
**启发式 pH 机器的读数与这组平衡方程在任何 pH 上都无法同时成立。**

**⟹ 结论与正确处置**：

* **不是**"需要更强的求解器" ⟹ **不要再投入求解器课题**；
* 真正的处置是**两者之一**（都是**表示层重构**，量级远超单课题）：
  (a) **让走步不进入这种态**（走步策略层）；或
  (b) **重写 pH 表示**，使启发式与平衡方程不再冲突。
* 附证：PHREEQC 无 pH 分支——pH 就是未知量，电荷平衡就是一条残差方程，
  Newton 直解。我们的 `joint.py::_solve_ph` **已经是这个形状**（pH 当第 m+1 个
  未知量 + 一条闭合行），**只差闭合行本身选错**。

### 1.2 "零推进"的两种形态（同一根因的两面）

| 形态 | 特征 | 例 |
|---|---|---|
| **pH 错型** | `pH_eng ≠ pH_chg` | `F31` / `H45` / `E43` / `M01` …（A+B 组 20 例）|
| **质子不可得型** | `pH_eng == pH_chg`（pH 本就对），但反应需质子而溶液质子稀缺 | `E41` / `T52` / `Y05` / `H35` / `X04` …（C 组 12 例）|

**共同机制**：`solve_extent` 的二分法收敛到 **pH 分支跳变**上
（`f(x)` 在 6e-6 内从 +21.5 掉到 −1.78），返回 `x*≈0` ⟹ `零推进` ⟹ `no-cands`。
**共同根因**：引擎是**逐通道贪心 + 局部求根**；当"通道需要质子"遇上
"溶液质子稀缺"，局部求根只能给 `x*≈0`，而全局上这些反应本应通过
**耦合（沉淀 / 溶解 / 酸碱再平衡）**继续推进。

**触发闸的坑**：`joint` 的第四个触发点（`no-cands` 前）条件含
`max(step) < 0.02`，**微步条件正是这一族 `joint_tries == 0` 的原因**。

### 1.6 ⚠️ 新缺陷（第 243 轮实测）：极稀强酸/强碱忽略水的自电离

在 `c ∈ [1e-8, 1e-6] M`，引擎把 pH 压到 **恰好 7.00**，而正解必须让
水的自电离参与电荷平衡：

| c / M | 精确 pH（HCl） | 引擎 | Δ | 精确 pH（NaOH） | 引擎 | Δ |
|---|---|---|---|---|---|---|
| 1e-5 | 5.0000 | 5.0000 | 0 | 9.0000 | 9.0000 | 0 |
| 1e-6 | 5.9957 | 6.0000 | +0.004 | 8.0043 | 8.0000 | −0.004 |
| 3e-7 | 6.4811 | 6.5200 | +0.039 | 7.5189 | 7.4800 | −0.039 |
| **1e-7** | **6.7910** | **7.0000** | **+0.209** | **7.2090** | **7.0000** | **−0.209** |
| 5e-8 | 6.8925 | 7.0000 | +0.108 | 7.1075 | 7.0000 | −0.108 |

**性质**：误差**有界（≤0.209 pH）且对称**，区间外（≥1e-5 或 ≤1e-8）消失；
**不是发散缺陷**，且对常规浓度无影响。**判据**：`1e-6 M` 档引擎正确，
`1e-7 M` 档错 —— 故 `S2`（1e-6）入库、`1e-7` 两档**只记账不入库**
（不为迁就引擎而曲解标准，也不把缺陷写成标准）。

但**真正的根因在拾取器**：

**走步的拾取是 `max(evals, key=S)` —— 纯 S 贪心。**
`S` 是**强度量**（驱动力多大），`ext_max` 才是**容量**（这一步能走多少）。
`N15 Na₂SiO₃+足量CO₂` 实测（`tools/crawl2.py` 末态探针）：

| 候选 | S | 可动量 `ext_max` |
|---|---|---|
| A `2H⁺ + SiO₃²⁻ -> H₂SiO₃`（precip）| **4.162** | **1.99e-4** |
| B `HSiO₃⁻ + H⁺ -> H₂SiO₃`（proton）| 4.077 | **0.5605** |

**两条路线产出同一固相**，B 的可动量是 A 的 **2800 倍**；贪心每轮都选 S 高
0.085 的 A，每轮只推进 1.99e-4，而 A 消耗掉的 `SiO₃²⁻`（**痕量族成员**）
立刻被 `HSiO₃⁻ -> SiO₃²⁻ + H⁺`（S 同为 ~4.2）补回 ⟹
`tools/crawl.py` 实测 **3000 次 `[pick]` 只在两个键之间交替**，
`H₂SiO₃` 停在 0.4393（真值 1.0）、退出 `max-iter`。

**修法**（`engine._pick_ev`，三条同时用，尽量窄）：
1. 只用**引擎既有**的显著程度线 `ANN_MIN_EXTENT`（`converg.resid_live_ok` 的
   `ext_max` 闸、`equations` 的净步取舍、slow 标注同用）—— **不引入新阈值**；
2. **只在同化学产物之间回退**（剔除 H⁺/H₂O 后的产物集合相等）—— 化学中性；
3. **先判首选**：S 最大者自身够显著时零开销直接返回，只有它痕量时才扫替代。

**否证记录**：**不要求同产物**的宽版残差多降 0.3，但**净丢 1 例通过**
且 `D08` 从残差 0 恶化到 4.32 ⟹ 收窄到同产物（数字见 `log.md` 第 264 轮）。
**性能**：第一版对每个候选算可动量 ⟹ 墙钟 65→141 s；改"先判首选"后 61–64 s。

**⟹ 结论**：`max(S)` 作为拾取规则在"同产物、多路线、容量悬殊"时必然错。
这条修法是**一般性**的（不针对 N15），触发面实测 **3.98%**（60,453 次拾取中
2,407 次改写），落在 **202/1309** 例上。

**原始诊断（保留备查）**：`charge_pH` 的账本语义是**元素总量账**（同族物种相加后
按 pH 再分配），走步的 `solve_extent` 却按"消耗物种"定 `x_max`；
两者叠加会让"被消耗的族内物种被再分配当即补回"。这个描述仍然成立，
但它解释的是**为什么爬行能自持**；**为什么一开始会选那条路**，答案是拾取短视。

### 1.14 ⭐ **「共轭形态重建」的正确粒度是「酸碱族」（第 273 轮推广）+ 暴露出的走步极限环**

**结论先行**：第 272 轮的准入判据（"伙伴不在本反应里"）**不够**。正确判据是
**族级**：**本反应里不得出现 `s` 所属酸碱族的其它形态**（`s` 自己不算）。
这条**蕴含**伙伴判据（伙伴按构造必在同族），化学含义也更强 ——
**当一条反应只是在讲某个酸碱族内部的形态互变时，该族的形态分布本来就是
账本自己的记账内容，用 Ka 重建等于把这条反应的 `S` 写成恒等式。**

**漏网实例**（`Ni41 NiCl2+NaHCO3`，第 272 轮把它从 0.859 推到 **11.964**）：

|---|---|---|---|---|
| `CO_2 -> CO_3^{2-} + 2H^+` | 都是 `HCO_3^-` | **否** | **放行（漏）** | 拦住（族内另一形态在）|
| `ClO^- + H2O -> HClO + OH^-` | 互为伙伴 | 是 | 拦住 | 拦住 |
| `Ni^{2+} + CO_3^{2-} -> NiCO_3` | `HCO_3^-` | 否 | 放行 | **放行**（族内只有 `CO_3^{2-}`）|

`HCO_3^- -> CO_3^{2-}+H^+` → `CO_2 -> CO_3^{2-}+2H^+` →

就与沉淀/再溶解凑成环。

**实现**：`_form_families(T)`（并查集，覆盖**全部** pKa 条目、不限 `n`，
T 级缓存）+ `S_of` 建计划时的 `_alt` 双闸。可用
`CHEM_NO_FORM_REBUILD=1` 关掉整个重建做 A/B（第 273 轮新增的 X-39 开关）。

### 1.17 ⭐ **滴定储备的「一步脱光」是错的：必须逐级、终止于固相（第 276 轮）**

**结论先行**：`_buffer_titration` 的**配离子碱储备**只读 `beta_pka:` 派生条目，
而那一族一律是**一步脱光到自由中心**：

    [M(OH)_k] + k·H⁺ -> M^{z+} + k·H₂O        （k = 梯级、z = 中心电荷）

⟹ 滴定器**无法在中途停在氢氧化物固相上**。而两性金属的正确第一步是

    [Al(OH)₄]⁻ + H⁺ -> Al(OH)₃(s) + H₂O       （**1 个** H⁺，不是 4 个）

**实测链**（`tools/ph_path.py`，新工具，把同一终态账本的**四路**并排）：

1. `H45 Na[Al(OH)4]+HCl 半量` 终态账本
   `Na⁺ 1 / Cl⁻ 0.5 / [Al(OH)₄]⁻ 0.874721 / Al(OH)₃ 0.125279 / He = +0.374721`
   电荷平衡 `1 + 0.374721 = 1.374721 = 0.5 + 0.874721` **逐位成立**
   ⟹ 自洽 pH = −log10(0.374721) = **0.426**；而引擎呈现 **12.19**。
2. 传入 `He = +0.37472143`，`_buffer_titration` 返回 `He_res = 0`，虚拟账本
   变化 `{'[Al(OH)_4]^-': −0.09368, 'Al^{3+}': +0.09368}`
   ⟹ `0.3747 / 0.09368 = 4.000` —— **按 4 个 H⁺/铝酸根吸收**。
3. 错法把账本留成 **0.78 M 铝酸根 + 0.094 M Al³⁺** 这种**不可能共存**的
   混合态；随后分支 4 / pinned 给出 12.185，让那 0.375 mol 游离强酸在走步
   眼里**彻底隐形**（`[Al(OH)₄]⁻ + 4H⁺ -> Al³⁺` 再也走不动）。

**修法（库内数据全可推，无新数据、无阈值）**：

    [M(OH)_k] + (k−z)·H⁺ -> M(OH)_z(s) + (k−z)·H₂O
    logK = (k−z)·pKw + pKsp − logβ_k

普查见 `tools/ladder_reserve_census.py`——**11 个**配离子，全部有值。
校验 `[Al(OH)_4]^-`：`1×14 + 33 − 34.5 = 12.5` ⟹ `Al(OH)₃(s) + OH⁻ ->
[Al(OH)₄]⁻` 的 logK = 14 − 12.5 = **+1.5**，与该 beta 条目自己的
`calibrated` 注记**逐位一致**。实现于 `_buffer_titration` 的静态预计算
（`_step`），`pkw_coeff = k−z`（logK 随 T 只通过 pKw 变），
`dH = e.dH − b.dH`（本条是上方 `ksp_beta` 的逆向）。

**修后实测**：滴定后的虚拟账本 = `{'[Al(OH)_4]^-': 0.5, 'Al(OH)_3': 0.5}`
—— **正是手算答案**（0.5 H⁺ 把 0.5 mol 铝酸根变固相）。

**顺带把第 275 轮的否证 A 重做成功**：第 275 轮"给含氧酸根补碱侧角色"失败，
**直接原因就是本条缺陷**——滴定把账本留成 0.78 M 铝酸根，再给它一个碱角色，
`o_c` 就被虚高浓度撑爆（`16 AlCl3+3NaOH` 从 Al(OH)₃ 变成纯铝酸根）。
先修储备再补角色，`16` 保持 pH **6.27**、`Y18` 保持 **11.71**、
`H43` 保持 **12.185**，三者都不动 ✓。

### 1.18 ⚠️ **"角色注入被重复的 `bases_map = {}` 整块清空"（第 277 轮）—— 一个静默清空类缺陷**

**结论先行**：第 276 轮把"含氧酸根 → 碱侧角色"写进了 `bases_map`，

**从第 276 轮起这个"判定"列就是错的**（角色来源还包括 `_first_k`/`hyd_map`/
含氧酸根碱侧角色）。改对之后立刻现形：`[Al(OH)_4]^-` **不在 182 项的
`rolemap` 里** ⟹ 分支 4 看不见 0.5 M 铝酸根 ⟹ `H45` 给 pH **7.0**（纯水默认）。
`tools/role_inject_check.py`（新工具，把静态块那几行**逐行重放**）
证明逻辑本身没问题（11 个含氧酸根、`[Al(OH)_4]^-` 得 Kb = 0.0316）
⟹ 一定是"写进去了又被清掉"，`grep bases_map` 立刻看到**两处定义**。

`rolemap` **182 → 193** 项，`[Al(OH)_4]^-` 拿到 `Kb = 0.0316`，
`H45` 的最终选支从 `h_c` 变成 `o_c = 0.110922`。

**本轮同时改正三条把"轨迹/表示"当化学的标准**（§7 W，第 275 轮的既有原则）：
* `N20 Na[Al(OH)4]+HCl少量` / `T51 NaAlO2+少量盐酸`：`eq_has` 要求
  `4H⁺ + [Al(OH)₄]⁻ -> 4H₂O + Al³⁺` 与 `3OH⁻ + Al³⁺ -> Al(OH)₃`，

* `U04 Al(OH)3 不溶氨水`：`eq` 要求两种**只差一个氨水解平衡**

### ⚠️ 数据问题（第 247 轮新查出）：8 条 pKa 的派生 dH 不可信

`data.py::_compute_dH` 按 Hess 从 `thermo.json` 派生
`dH = ΔfH(碱) − ΔfH(酸) − w·ΔfH(H₂O)`。**公式没问题**（HCN/NH₄⁺/H₂S/HClO
等对拍 Δ ≤ 0.003 已验证），问题在**输入 ΔfH**。`tools/dh_audit.py` 按
"|ΔH| > 60 kJ/mol（一元质子解离的经验上限）或 |ΔpKa(273→373)| > 3"
筛出 8 条：

| pKa 条目 | pKa298 | dH | ΔpKa(273→373) | 可疑原因 |
|---|---|---|---|---|
| `HIO_4` | 1.6 | **+399.0** | **20.45** | ΔfH=−550 是**固态** HIO₄（NIST≈−536），被当水相用 |
| `HVO_4^{2-}` | 12.5 | +243.0 | 12.45 | ΔfH 记录 (−1180/−937) 待核 |
| `HClO_4` | −10.0 | −119.3 | 6.11 | ΔfH=−10 vs 文献 HClO₄(aq)≈−40 ⟹ dH 抬高约 3 倍 |
| `H_3VO_4` | 3.5 | +86.0 | 4.41 | 同上（V 族）|
| `HClO_3` | −1.0 | −81.0 | 4.15 | 卤氧酸族 |
| `H_2WO_4` / `HWO_4^-` | 3.5 / 4.8 | +71.0 / +70.6 | 3.64 / 3.62 | W 族 |
| `H_2VO_4^-` | 7.8 | +64.0 | 3.28 | V 族 |

**后果**：`HIO_4` 在 373 K 被外推成 pKa = −12.4（比高氯酸还"强"两个数量级），
pH 求解随之失效（`0.01 M HIO_4` 半中和：应 1.60、引擎 2.43；373 K 应 −12.45、
引擎恒 2.30）。**处置**：**不自行改 ΔfH**（须逐条查文献并核**相态**），
先记账；**在这 8 条上不要写温度断言**。判据与清单见 `tools/dh_audit.py`。

**第 248 轮定位（缩小到"中性酸"这一小类）**：与 `llnl.dat` 逐条对 ΔfH
（`tools/thermo_xcheck.py`）后确认：
* **阴离子是校准过的** —— `IO_4^-`=−151.0 对 llnl −151.4；
  `ClO_4^-`=−129.33 对 −129.3（llnl 的 `-36.2 / -30.91 kcal/mol` 换算值）；
* **llnl 里根本没有 `HIO_4` / `HClO_4` 这些中性酸物种** ⟹ 问题**只在中性酸**；
* 全库 329 条 thermo 里能与 llnl 对上名的 14 条中，差 > 20 kJ/mol 的只有 3 条
  （`AgCl` / `PbCl_2` / `SiO_2`），**且三条都是相态差异**（我们存**固体**、
  llnl 存**水相/无定形**）⟹ **库内 ΔfH 总体是可靠的**，不是普遍失准。

**⚠️ 这是潜在缺陷、不影响当前任何用例**：61 条非常温用例**没有一条**投料含
{I, V, W, Cl 的含氧酸} ⟹ 现有套件结果不受影响；但它是个陷阱（谁写这些体系的
温度断言就会踩到）。

### ⚠️ 死数据（第 249 轮实测）：`logk_poly.json` 命中率 **0**

**接线是有的**：`candidates._poly_logk` 在 `logK_T`（L461-468）里**优先于**
van't Hoff —— 命中就用多项式（含热容项，比单一 dH 更完整），未命中才回退。
**但实测一条也命中不了**：

| 项 | 实测 |
|---|---|
| 150 例抽样产生的候选键 | **524** 个 |
| 其中命中多项式表的 | **0** |
| 抽查 120 例的 `_poly_logk` 调用 | 命中 **0** / 4552 次 |

**三个独立原因（都已定位）**：
1. **`H+` 未归一化进键**：`_poly_key` 剔除的是 `H_ION` 常量（`"H^+"`），
   而 PHREEQC 风格反应式里写作 `H+` ⟹ `_poly_norm("H+")` = `"h"` 留在键里。
   实测：`Na+ + F- = NaF` 存储键 `('f','na','naf')`、按运行时重造也是
   `('f','na','naf')` ✓；但 `H+ + 2 F- = HF2-` 重造得 `('f','h','hf2')`
   而存储键是 `('f','hf2')` ✗。
2. **固相条目键口径不同**：54 条里有 30 条是**纯固相条目**
   （`gypsum`/`barite`/`calcite`/`aragonite`/`chrysotile`…），键就是固相名本身，
   与我们的 `Cand` 键构造方式不同构。
3. **体系大多不相交**：把这些反应式的物种按运行时口径归一后与库内
   **709 个物种**求交，只有 **13/71（18.3%）** 命中，且多是 `SO_4^{2-}`/
   `HPO_4^{2-}`/`CO_3^{2-}` 这类通用离子出现在固相条目里。

**处置：不冒险改键** —— 原因 3 决定"只修键也换不来命中"，而修键有真实风险。
正确做法是**重造映射层**（按反应式的物种集合 + 我们自己的 `_poly_norm`
重新生成键，并对固相条目单独建模），**列为 P0 待办**。
**影响面 0**：现在没有任何用例走这条路径，所以它是**死数据而非缺陷**；
但热容项本可比 van't Hoff 更准，接线后对**非常温**用例是实质改进。

**第 250 轮：这条路线已**关闭**（有决定性证据）**。`tools/poly_map_check.py`
跑**全部 1230 例**、收集真实运行的 **1034 个候选键**，再对 54 条按运行时口径
**重造键**（已剔 `H+`/`H2O`，即修好第 249 轮查出的归一化漏项）：
**重造键 ∩ 真实候选键 = 0**。而且找到**真正的根障碍**：

| 存储键 | 我们的 `_poly_norm` 会得到 |
|---|---|
| `'mg'`（来自 `Mg+2`）| `'mg2'` |
| `'na'`（来自 `Na+`）| `'na^'` |
| `'k'`（来自 `K+`）| `'k^'` |
| `'f'`（来自 `F-`）| `'f^'` |

**表的键把电荷整个丢掉了**（`mg` 既可能是 Mg²⁺ 也可能是 Mg(s)）——
**有损且不可逆**：我们无法从 `'mg'` 恢复出电荷。故"重造映射层"**不是工程量大，
而是方案本身不成立**。**正确处置**：要利用这 54 条，只能**扩大套件的化学体系**
（HF/氟化物、硫化物、石膏/重晶石、EDTA 族），而不是修键。**路线关闭，不再投入。**

### ✅ 第 263 轮：**`estimate_pH` 分支 4「两性中点」的模型性错误**（已根治）

**缺陷**：分支 4 的 `pH = (pKa1+pKa2)/2` **不是独立模型**，而是质子条件的
**近似**——由 `[H₂A] = [A²⁻]`（**丢掉 h 与 oh**）推出，并默认「该两性物种是
**唯一**的质子条件物种」。**共轭伙伴同时在账**时，`[H₂A]` 由**投料**定、
不由歧化定 ⟹ 那是**缓冲对**，前提整个不成立 ⟹ **用错模型，没有容差能修**。

| 体系 | 中点式 | **精确解** | Δ | 性质 |
|---|---|---|---|---|
| H₂S 半中和 298 K（`TC3`）| 10.500 | **7.0000** | **+3.50** | **模型错** |
| CO₂ + NaOH 1:1 | 8.350 | **6.3999** | **+1.95** | **模型错** |
| 纯 NaHS 0.01 M | 10.500 | **9.4972** | +1.00 | 近似误差 |
| 纯 NaHCO₃ 0.01 M | 8.350 | **8.3456** | +0.004 | 近似误差（教科书体系恰好准）|
| 纯 NaH₂PO₄ 0.01 M | 4.650 | **4.7775** | −0.128 | 近似误差 |

**修法**：两性支路在「伙伴在账（`_pair`）+ 账本过 `_exact_ok` 闸」时
**先问精确质子条件**（`charge_pH`）；纯两性盐一侧**本轮明确不修**（见 §4 P0）。
同时把原先内联在 `_deg` 路径的三条闸抽成 `_exact_ok()` **两处共用**。

**判据**：`tools/amph_exact.py` 的**引擎无关闭式解**（只用库内 pKa 与 Kw），
在 5 个体系上与 `charge_pH` **逐位吻合 4 位小数**（含两个已知错例）。
正/负对照 `--calib` 先通过再判案。

**触发面**：`tools/amph_survey.py`（把 `_tag` 换成计数器，**零侵入**）实测
中点支路仅占 **1,314,020 次调用的 0.71%**（9,362 次）⟹ 性能无碍。
（对照：滴定/Henderson 40.7%、酸侧max 36.6%、碱侧max 20.2%。）

**实测**：残差质量 **332.9 → 325.7（−7.24）**、`n(|S|>0.1)` 205→202、
`n(|S|>1)` 61→59、`resid_max` 25.415 不变、数值漂移仅 **6 例**；
`TC1/TJ3/TC3` **3.5–3.7 → 0.0**；测试库 **+8**（两性缓冲对锚，8/8 全过）。

⚠️ **同轮暴露 `N15` 微步爬行**（PASS→FAIL）—— 见 §1.7 与 §5 缺陷表；
**不是 pH 错**（精确解经手算复核），是**错误相互抵消**被翻出来。

### 开放线索（**已结案，勿重开**）

**镧系盐溶液 pH 的歧义**（第 242 轮提出、第 243 轮结案）。实测：

| 事实 | 实测 |
|---|---|
| 引擎 | `0.01 M LaCl₃` pH **5.25**、无固相、`max\|S\|=0` |
| 引擎**已生成**固相候选 | `{"kind":"precip","eq":"La^{3+} -> La(OH)_3 + 3H^+","S":-8.25}` ⟹ **未饱和是对的** |
| 把"质量+电荷"联立的代数根 | pH **2.0000**（α≈100%）**与** pH **6.88**（α≈0.009）**两个根** |
| 实验观测（LaCl₃ 溶液） | **≈5.2** —— 与引擎一致，**与上面两个根都不一致** |

**结论（明确记下来，避免再查一遍）**：
1. **引擎的固相判定没错** —— 它确实生成了 La(OH)₃ 候选并算出 S=−8.25（未饱和）。
2. **代数多根**是这类体系的真实性质（稀土只有 ν=1 的水解常数，模型不完整）。
3. 引擎走的是**碱度平衡（虚拟强酸 H_excess）**口径，不是"物种级电荷平衡"口径；
   两者在**只有单一水解物种、且库内只有 ν=1** 时会给不同 pH（此处差 1.6）。
4. **引擎值恰好与实验一致**，而代数根与实验都不一致 ⟹
   **在库内补齐稀土 ν≥2 的水解常数之前，任何一方都不能判对方错**。
   **不要**在这条线上改引擎（改不动根因，只会拟合）。

## 8. 纪律（不可违背，详见 lessons.md / discipline.md）

* **一切以化学事实为准**；不为迎合测试标准而舍弃更本质的做法。
* **不凑合**：不用指标不治本的小补丁；根源解法暂时失败也不直接抛弃
  （第 198→201 轮即此范例：pinned 首版变差，查明病根后修好而非回退）。
* **数据与引擎缺陷分开记账**，不许互相掩盖（`db_matrix` 出清单）。
* **测试库标准可能有错**：先问"这是化学事实，还是某次引擎输出的快照"。
* 记忆值**不得**当已核数据：查不到出处就**不入库**，或写
  `calibrated: provenance 未核实` 并单列待复核。
* 数据改动走 `dev.py patch` 或 `tools/jsondb.py`（**按键路径**）。
* **改闸 / 守卫前先量爆炸半径**（`gateface` / `gatefilter` / `gate_relax` /
  `narrowband`）：先枚举"新放行集合"并逐例核对，再动手。
  **"判据看起来更对" ≠ "改动更安全"。**
* **改代码前先校准测量工具**：用**判据已知**的用例（正对照 + 负对照）验证探针
  本身有判别力。**注意有固相时 β 比值被违反是合法的**（Ksp 钉住自由金属），
  故 `selfcheck.py` 类检测器此时**必误报**。
* **验收指标要问它由哪一段决定**：`resid_p90` 由散乱小残差决定 ⟹ 不作主线。
* **跳变区间里任何求根都会落在跳变上**（否则会反复"优化"到分支边界）。
* **表述错了，修法必然错**：先核对探针表述（口径）再下结论。
* **每轮**：建 / 更新 `todo`（**实时**标记完成）→ 一次运行全量结构化留档（`logs/`）
  → 轮末更新本文件 + `lessons.md` + 提交 + 汇报指标。
* **子代理纪律**：测量 / 实现类任务可派给子代理以省主上下文；
  ① **要求落盘**（`tools/<name>.py` + `logs/<name>.json`），中断也不丢成果；
  ② 返回后立即终止，不空转；③ **审计 / 测量类子代理运行期间冻结 `chemkit/`**，
  不得并行编辑；④ 成果**必须合并或引用**进正式产物（本文件 / `lessons.md` /
  `tools/`），不得散落丢弃。
* **本文件更新时机**：每轮完成后、以及轮内**阶段性目标**完成后即时更新，
  不留到轮末补记。
