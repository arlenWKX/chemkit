## 3. 下一步（**优先级最高，已定位**）

### 3.0 ⭐ **Pitzer 修正（使用者特别指出：后续需落实）**

**现状（第 203 轮核实）**：`chemkit/data/pitzer.json` 已有 **426 条结构化 Pitzer
参数**（`b0` 84 / `b1` 77 / `b2` 19 / `theta` 58 / `psi` 165 / `zeta` 17 /
`lamda` 6，来自 pitzer.dat / frezchem.dat / ColdChem.dat / Concrete_PZ.dat），
但 **引擎零消费**（`chemkit/*.py` 里检索 `pitzer|PITZER` 无命中）——是**死数据**（D4）。

**为什么要做**：当前活度层是 **SIT**（`Δz²·A√I/(1+1.5√I) + ε·I`），
其适用上限约 **I ≤ 3–6**；而库内用例有 1 M 级电解质（I 可达 6+），
**高浓卤水区间只有 Pitzer 才准**。数据已就位 ⟹ 这是"数据等引擎"的典型。

**落实方案（建议分步，每步可独立验收）**：
1. **建 Pitzer 活度模块**（如 `chemkit/pitzer.py`）：实现
   `lnγ± = lnγ(DH) + Σ_j m_j·(2B_Mj + Z·C_Mj) + …`（β⁰/β¹/β² 与 Cφ 的
   标准 Pitzer 形式；θ/ψ 为混合项、λ/ζ 为中性-离子项）；
2. **接线点**：与现有 `logK_T(c, T_K, I)` 同层——把"离子强度修正"抽象成
   `activity_model ∈ {SIT, Pitzer}`，按开关切换（`CHEMKIT_ACT=pitzer`），
   这样可**逐族对拍**（同用例跑 SIT/Pitzer 两版，比较 pH 与形态）；
3. **验收判据**：① 高浓用例（1 M NaCl/NaClO₄ 介质）的 pH 与文献锚比较；
   ② 与 SIT 版逐例 diff，位移方向应符合 Pitzer 的已知行为（高浓下
   β¹ 项使 γ 回升）；③ 全套件指标不得比 SIT 版更差（iters/resid）。

**依赖与风险**：① 需要 Pitzer 的**温度依赖**（库内部分条目带 T 多项式系数，
已在 `vals` 里原样保留）；② 需要**电荷/离子配对**匹配（库用 PHREEQC 命名，
需 `tools/phq_parse.py` 的映射）；③ 实现量大，建议**先只在 `I > 3` 启用**
（SIT 在低浓已足够），降低爆炸半径。

## 10. 纪律（不可违背，详见 lessons.md / discipline.md）

* **一切以化学事实为准**；不为迎合测试标准而舍弃更本质的做法。
* **不凑合**：不用指标不治本的小补丁；根源解法暂时失败也不直接抛弃
  （第 198→199 轮即此范例：pinned 首版变差，查明病根后修好而非回退）。
* **数据与引擎缺陷分开记账**，不许互相掩盖（`db_matrix` 出清单）。
* **测试库标准可能有错**：先问"这是化学事实，还是某次引擎输出的快照"——
  但本轮核对的 E55/N22/T51/16 标准都是化学事实，不许动。
* 一切数据改动走 `dev.py patch` 或 `tools/jsondb.py`（**按键路径**，不用文本锚串）。
* 记忆值**不得**当已核数据：查不到出处就**不入库**，或写
  `calibrated: provenance 未核实` 并单列待复核。
* 每轮：**建/更新 todo**、一次运行**全量结构化留档**（`logs/`）、
  轮末入档 `log.md` + 更新 `lessons.md` + 提交 + 汇报指标。
* **子代理使用纪律**（使用者明确要求）：测量/实现类任务派给 coder 子代理
  （`resume="agent-0"` 续用）以省主上下文额度；**子代理返回结果后立即
  终止、不挂空转**，需要续跑再 resume。
* **handoff.md 更新时机**：每轮完成后、以及轮内**阶段性目标**完成后都要
  即时更新（§0 指标、§3 任务状态），不留到轮末补记。
