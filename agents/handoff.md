## 3. 改代码前必须知道的约定

### 3.1 三层视图（判"引擎错还是断言错"的第一动作）

| 层 | 取法 | 性质 |
|---|---|---|
| 账本 | `judge(..., _probe=pr)["ledger"]` | 化学真值所在 |
| 净差 | 引擎渲染的 `initial -> final` 之差 | 引擎自己的解释 |
| 呈现 | `Reaction.consumption/production/final` | `testsuit` 的 `has*` 只读这层 |

工具：`tools/specdist.py <前缀>` 三层并列。

### 3.2 动力学"慢"的表征（易错）

* `slow`（配对级，两方向恒慢）⟹ 方向未定前可整条跳过；
* `slow_dirs`/`sd_static`（**方向级**）⟹ 只能由**逐方向**消费点读；
* `slow_T`/`halate_rule`（带温度门）⟹ 温度相关者不能进预组装快路径；
* 有序对语义：**正向 = `a.ox` 被还原 + `b.red` 被氧化**；`a.ox == X` 表示 X 是
  **氧化剂**（被还原），`b.red == X` 才是"X 作还原剂"。

### 3.3 断言纪律要点

* 只锁**化学事实**（pH、总产量、特征步）；`changed`/`degree` 等语义位移**不作门槛**
  （`discipline.md` §三）；
* 重裁要**能卡掉旧值**（新窗排除旧引擎值）＝ 加强，不是放松；
* 数据缺口与引擎缺陷**分开记账**；回退先比 pH + 物种量 + `eq`，化学一致则改断言。
