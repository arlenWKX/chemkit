### 2.2 F31 根因（**已确认，可直接接手修**）

用例：`F31 GaCl3+3NaOH`（1 mol GaCl₃ + 3 mol NaOH）。**套件 FAIL**。

| 项 | 值 |
|---|---|
| 严格化学正解（引擎自己的常数解出） | **pH 5.764**，Ga(OH)₃(s) 析出 **0.999998 mol** |
| 引擎实测 | **pH 1.62**，固相 **0**，余额 `[Ga(OH)₄]⁻ 0.743 + Ga³⁺ 0.253` |

**根因（唯一缺陷，其余环节均已被实验排除）**：
`estimate_pH(ledger, He)` 在 `He` 跨过**账本自身电荷不平衡量**时**硬切换分支**：

```
同一账本 {Ga³⁺ 0.253447, [Ga(OH)₄]⁻ 0.743147, [Ga(OH)]²⁺ 0.003406, Na⁺ 3, Cl⁻ 3}
  He = −0.024007  → pH 12.380338   ← 与账本电荷自洽值(−Σz·n = −0.024007)分毫不差 ✓
  He = −0.020000  → pH  1.619665   ← 错，差 10.76 单位
  中间是**完全平台**（−0.001…+1e-4 同为 1.310882/1.619665）⟹ 分支硬切换，非噪声
```

该账本的 `−Σz·n` **恰好落在这个悬崖上**，引擎读了错误一侧 ⟹ 报 1.62。
后果链：1.62 使沉淀候选 `Ga³⁺+3H₂O→Ga(OH)₃+3H⁺` 得 `S = −3.973`（判为**不饱和**）
⟹ 固相永不析出；而正确读数 12.38 会给 `S = +25.013`（强过饱和）⟹ **会触发析出**。
**这就是"归中接力不发生"的全部原因。**

**修法必须窄**（两条更宽的方案已被实测否决，见 §3.2）。

### 2.3 同族缺陷面（不是 F31 独有）

109 例断言金属氢氧化物固相的用例中：**正常 102 / 同缺陷 4 / 其它 3**。
同缺陷 4 例：`F31`（Ga，**欠饱和**侧）＋ `H43 AlCl₃+NaOH 1:3.5`、
`H45 Na[Al(OH)₄]+½HCl`、`M03 Na[Al(OH)₄]+少量HCl`（Al 三例为**过饱和**侧，
沉淀腿 `S=+25.0~25.3` 却被标 `零推进` ⟹ 该析出而不能析出）。

**引擎"能"做对的反例**：`16 AlCl₃+3NaOH`→0.9978、`N10 CrCl₃+3NaOH`→0.9999995、
`H48 FeCl₃+3NaOH`→1.0000000、`I31 InCl₃+3NaOH`→0.99975、`S32 SbCl₃+NaOH`→0.9999999，
外加 Sc/Y/Nd/Gd/Ho/Tm/Rh/Ru 等 9 个三价金属。**它们的第一步与 F31 完全相同**
（`M³⁺+4H₂O→[M(OH)₄]⁻+4H⁺`, ext≈0.749），区别只在**随后能否经
`[M(OH)₄]⁻+H⁺→M(OH)₃` 把固相捞回来**。

## 3. 下一步（**优先级最高**）

### 3.1 修 F31 根因（**已定位到机制层，见下**）

> 三次重新定位的过程与逐条否证见 `log.md` 第 207/208/209 轮。
> 第 207 轮否掉"改接线"、第 208 轮否掉"改弱酸式"，**第 209 轮找到了真正的机制**。

**✅ 根因（第 209 轮实测，`tools/f31trace.py` + `tools/extzero.py`）**

走步不是"候选耗尽"、也不是"退出判据太早"。逐迭代轨迹显示**候选被正确挑中**：

```
[pick] Ga^{3+} + 3H2O -> Ga(OH)_3 + 3H^+   1   28.32      <- 沉淀腿被选中，S=+28.3
  [ext] 0.0            pH 12.38   He -0.0241              <- pH 也正确
  [micro] **零推进（S 强而 x*≈0）** x_max=0.256 ext=0
```
⟹ **是 `solve_extent` 给出 `x* = 0`**，于是无步可走 ⟹ `no-cands`。

而在**该步起点上手工扫 `S_of(x)`**（`tools/extzero.py`），拿到的是**双模态**：

| x | estimate_pH | S(x) |
|---|---|---|
| **0** | **1.620** ← 酸侧 | **−3.973** |
| 1e-06 | **5.764** ← 碱侧 | **+8.459** |
| 5e-03 | 5.764 | +8.466 |
| 1e-02 | 1.627 | −3.952 |

⟹ **`estimate_pH` 在 `x=0` 这个态上取酸侧（1.62），而挪动 1e-6 就翻到碱侧
（5.764 = 严格解！）**。`solve_extent` 因此在 `f(0) = −3.97 < 0` 起手，
按"括号内无过零点"返回 `x*=0`。
**这就是 F31 死锁的最后一环**：不是候选、不是退出判据、不是二分算术，
而是**二分起点上的 pH 双模态**（同一账本、He 差 1e-6，pH 差 4.1 个单位）。

**⟹ 修法目标（下一轮）**：让 `estimate_pH` 在**同一账本**上不因 He 的
1e-6 级扰动而换枝。已知的"酸侧来源"是弱酸二次式（第 208 轮：Ga³⁺ 的
β 路线 `h=0.0240`），但它**不能单独修**（第 208 轮实测更差）。
可行的窄修法：**仅当"账本里没有 pKa 质子族成员"时**，让 `estimate_pH`
用 `acidbase.charge_pH`（它在这种账本上是精确的——族总量无歧义、
非族物种直接进电荷方程），因为此时**没有 Henderson/族分布可言，
诱导式分支本就是唯一依据**。这比"全局接管"窄得多（第 206 轮实测全局
接管有 156 例差 >1），**但必须先量化该条件的命中面**。

**⟹ 修法条件已定（第 210 轮量化，爆破半径 = 1 例）**

条件（**同时**满足才让 `estimate_pH` 改用 `acidbase.charge_pH`）：
```
(a) 账本里**没有 pKa 质子族成员**（此种账本无 Henderson/族分布语义，
    诱导式分支本就是唯一依据，charge_pH 在此精确）
(b) **无固相在场**（有固相时 charge_pH 已知会错：它把总量当溶解量）
(c) 引擎**自认未达平衡**：`max_abs_S > 3`
    （这一条是关键判别：另有 67 例满足 (a)∧(b)∧|ΔpH|>1，但它们
      `max_abs_S = 0.0`——引擎自认已平衡，Δ 只是建模差异，不该动）
```
**实测爆破半径**（`tools/nofam.py`，全库 1147 例，读档不重跑）：
* 只加 (a)：命中 **640 例**（含 563 例 PASS）⟹ **太宽，不可用**。
* (a)∧(b)：281 例（232 PASS）；再 ∧|ΔpH|>1：68 例（51 PASS）⟹ 仍太宽。
* **(a)∧(b)∧`max|S|>3`：命中 1 例——恰好只有 `F31`** ✓
  （`max|S|>1` 会多出 N21/M04/U11 三例；取 >3 得唯一解）

**❌ 第 213 轮：放宽入口条件**已实测否决（`tools/gate_relax.py`，全库 1147 例）

| 变体 | 会改变的例 | 其中**当前 PASS** | \|Δ\|>1 |
|---|---|---|---|
| V0 现状（`_nf>=2 ∧ \|net+He\|<=1e-6`） | 202 | **171** | 5 |
| V1 去"循环条款"（只留 `_nf>=2`） | 202 | **171** | 5 |
| V2 去循环条款 + 放宽 `nfam` | 363 | **285** | 75 |

两个决定性结论：
1. **V0 ≡ V1** ⟹ `abs(_net + He_res) <= 1e-6` 对真实账本**几乎不可满足**，
   那条"精确解接管"路径**长期处于休眠**（这正是它没救下 F31 的原因）；
   去掉该条款会一次性激活 **202 例**。
2. **但那 202 例里 171 例当前是 PASS 的**，且 `charge_pH` 在它们身上**是错的**：
   `CuSO4 水解`/`H2+CuSO4`/`KNO3+CuSO4`/`SH8`（引擎 **4.0** 对，charge_pH **7.0** 错）、
   `FeCl3+Cu`/`O04`/`RX2`（4.311 vs 7.0）、`D05`（4.399 vs 7.0）……
   原因即已知的 `charge_pH` 边界：**它把账本里的总量当溶解量**，凡"账本已把金属
   记成离子/配合物、而真实溶液还有别的分配"的态，它就给出 ±3 单位的偏移。

⟹ **"循环条款"看错了角色**：它不是循环论证，而是**在替 `charge_pH` 把关**——
要求"账本与 He 自洽"恰好挡住了 `charge_pH` 不可信的那些账本。
**这也是第 203/206/211/213 四次否决的共同原因**：`charge_pH` 本身在
"账本欠定/总量当溶解量"的态上不可信，**无论怎么加条件放行都不安全**。

**⟹ 结论：`charge_pH` 这条路彻底封死。** 真正的判别不在"账本自洽与否"，
而在**引擎自认的残差**（F31 `max|S|=13.3` vs CuSO₄ 类 ≈0）——但该量在
`estimate_state` 内部不可得（要枚举候选）。**故下一轮方向改为：
不再动 pH 求解器，转而处理"走步为何停在热力学不自洽态"**
（即 `solve_extent` 起点处的自洽性/收敛判据），或接受 F31 为已知开放缺陷。


`estimate_state` **早已实现**"退化区精确质子条件接管"（第 197 轮，L905-1010），
且 F31 **确实落在退化区**（`h_c/o_c` 比值 2.4 ∈ [0.1, 10] ⟹ `_deg` 为真）。
**但接管被同一段里的两个子条件挡掉**（L1006）：

```python
if not _res and _nf >= 2 and abs(_net + He_res) <= 1e-6:
```
* `_res`（无固相）✓ 通过
* **`_nf >= 2`（≥2 个 pKa 质子族成员）✗** —— F31 的 `nfam = 0`
  （镓羟合梯在 **beta** 表，账本里没有 pKa 族）
* **`abs(_net + He_res) <= 1e-6` ✗** —— F31 是 **0.024**

**而第二个子条件是循环论证**：它要求"账本已经电荷自洽"才允许调用
`charge_pH`——可 `charge_pH` 的**全部职责就是解出那个让账本自洽的 pH**。
先要求答案再允许求解，等于把这条修法永久锁死。

**分支判决的精度也已定量**（`PH_SRC` 实拍，同一账本只改 He）：

| He | `h_c`（Ga³⁺ Ka 式） | `o_c`（−He） | 胜者 | pH |
|---|---|---|---|---|
| −0.024000 | **0.02400682** | 0.024000 | `h_c`（**仅大 2.8e-6**） | **1.6197** |
| −0.024007 | 0.02400682 | **0.024007** | `o_c` | **12.3803** |

⟹ **pH 由 3e-6 的相对差决定**，是 D13 的教科书案例（同一质子失衡的两种记法
在 `max` 处竞争，浮点末位定胜负）。

**⟹ 修法（下一轮，方向已明确且极窄）**：把退化区接管的入口条件从
"要求账本已自洽"改为**允许账本不自洽**（那正是要解的量），即
* 去掉 `abs(_net + He_res) <= 1e-6`（或放宽为"两侧量级相当即接管"），
* 并把 `_nf >= 2` 放宽为"**或**账本里有 beta 梯物种"（F31 属此）。

**必须先用因果模拟验证**，再做套件存档对拍。**这一条与第 203/206/211 轮
被否决的三种方案都不同**：那三次是"在 `estimate_pH` 外面加条件放行"，
这次是**修 `estimate_state` 内部那个循环论证的入口条件**（机器早就在，
只是被一把错误的锁锁着）。

**方法论**：`estimate_pH` 的分支是本仓最敏感处。第 207/208 两轮各有"看起来
必然正确"的修法被实测否掉。**任何改动先做因果模拟 + 存档对拍。**

3. **4 处 `closed_pH → estimate_pH` 降级复制**（engine L400-402、L493-498、
   L1584-1585、L2248-2250）收敛为单一辅助函数。
4. **验收**：同一 `(ledger, He)` 的**所有** pH 通路差异 < 0.01
   （用 `chargeprobe.py` + `phaudit.py` 全库回归）。

> **架构参照（PHREEQC，`thirdparty/phreeqc-3.8.6-17100/src/model.cpp`）**：
> 它**不做 pH 分支估计**——pH 是**未知量**，**电荷平衡是残差向量里的一条方程**
> （L325/L3841 `ph_unknown == charge_balance_unknown`），一起 Newton 迭代（L105）。
> 我们的 `joint.py::_solve_ph`（L246-262）已实现同构机制，但 L291 的闭合行用的是
> 同一个不连续启发式。**长远方向 = 让 pH 由守恒方程解出，而不是由分支估出。**

### 3.4 质量缺口

* **`resid_p90` 0.447 → ≤0.1**（`n(|S|>0.1)`=200）。已定位两族：
  Al³⁺/Cr³⁺ 碱量不足、卤素计量上限（后者已结案：痕量反应物计量上限，非缺陷）。
  **验收**：`resid_p90 ≤ 0.1` 且 `resid_max` 不升。

## 8. 纪律（不可违背，详见 lessons.md / discipline.md）

* **一切以化学事实为准**；不为迎合测试标准而舍弃更本质的做法。
* **不凑合**：不用指标不治本的小补丁；根源解法暂时失败也不直接抛弃
  （第 198→199 轮即此范例：pinned 首版变差，查明病根后修好而非回退）。
* **数据与引擎缺陷分开记账**，不许互相掩盖（`db_matrix` 出清单）。
* **测试库标准可能有错**：先问"这是化学事实，还是某次引擎输出的快照"。
* 一切数据改动走 `dev.py patch` 或 `tools/jsondb.py`（**按键路径**）。
* 记忆值**不得**当已核数据：查不到出处就**不入库**，或写
  `calibrated: provenance 未核实` 并单列待复核。
* **改闸/守卫前先量爆炸半径**（`gateface.py` / `gatefilter.py` / `jointclose.py`）：
  先枚举"新放行集合"并逐例核对，再动手。**"判据看起来更对" ≠ "改动更安全"。**
* **改代码前先校准测量工具**：用**判据已知**的用例（正对照 + 负对照）验证探针
  本身有判别力（第 204 轮：未经校准的自洽性检测器把 PASS 例报得比 FAIL 例还糟）。
* **每轮**：建/更新 `todo`（**实时**标记完成）→ 一次运行全量结构化留档（`logs/`）
  → 轮末更新本文件 + `lessons.md` + 提交 + 汇报指标。
* **子代理纪律**：测量/实现类任务可派给子代理以省主上下文；
  ① **要求落盘**（`tools/<name>.py` + `logs/<name>.json`），中断也不丢成果；
  ② 返回后立即终止，不挂空转；③ **审计/测量类子代理运行期间冻结 `chemkit/`**，
  不得并行编辑（否则它读到变动中的树，结论作废）。
* **本文件更新时机**：每轮完成后、以及轮内**阶段性目标**完成后即时更新，
  不留到轮末补记。
