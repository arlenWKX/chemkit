### ⭐ 第 203 轮重大进展：F31 形核帧缺陷**根因已定量坐实**（可直接接手修）

**结论（一句话）**：F31 的病根**不在沉淀/形核，也不在酸碱预算**，而在
**`estimate_pH` 在 `He = 0.0` 处的一个阶跃悬崖**：二分求根把这个**阶跃**
当成了平衡根，于是第一个执行步跨过悬崖、一步把 3 mol 强碱变成 2.98 mol
强酸。这是一次 **D14/D15 类"接缝被当成平衡"** 缺陷，不是数据缺陷。

**实测证据链（全部可复现，工具已入库 `tools/f31_*.py`）**：

| 项 | 值 | 出处 |
|---|---|---|
| 起始态 | ledger `{Ga³⁺ 1, Na⁺ 3, Cl⁻ 3}`, `He=-3.0`, `estimate_pH=14.477` **✓ 化学正确** | `tools/f31_init.py` |
| 严格化学正解 | **pH = 5.764**，Ga(OH)₃(s) 析出 **0.999998 mol** | `tools/f31_exact.py` |
| 引擎实测 | **pH = 1.62**，固相 **0.000**，余额 `[Ga(OH)₄]⁻ 0.743 + Ga³⁺ 0.253` | `tools/f31_probe.py` |
| 偏差 | pH 差 **4.14** 单位；固相差 **1.000 mol** | |
| 走步代价 | 仅 5 迭代 / 3 步，`exit=no-cands`，`joint_tries=0`、`cycle_jumps=0` | 同上 |

**缺陷机制（`tools/f31_scan.py` 的 f(x) 细扫，逐点定影）**：

```
反步 Ga^{3+} + 4H2O -> [Ga(OH)4]^- + 4H^+   (S(0)=+50.463, solve_extent ext=0.743966)
     x        pH_est        He          S(x)
   0.743      12.447      -0.028      +30.011     ← He<0 侧：正确
   0.750       1.623      +0.000      -13.303     ← He=0 悬崖！S 跳变 43 个数量级
```
* 两侧化学**都**不可能：He=-0.028 ⟹ pOH=1.553 ⟹ [OH⁻]=0.028 ✓ 自洽，
  但 S=+30 说"还要继续产酸"；He=0 侧 [H⁺] 应为 ~2.25 M（电荷平衡）而报 1.62。
* **`estimate_pH` 只在 `He = 0.0` 出错**（实测：He=-3.0→14.477、
  −1.0→14.0、−0.024→12.38 全对；**He=0.0→1.623 ✗**）。He<0 走分支 3
  强碱（`[OH⁻]=−He/V`，正确）；He=0 落入分支 4 启发式并被"酸侧"独占。
* 二分在 x∈[0.743, 0.75] 见 S 由 +30 变 −13 **⟹ 判定有根 ⟹ 取 ext=0.744**。
  **它收敛到的是阶跃，不是平衡。**

**⭐ 最后一层已定影：引擎的 (ledger, He, pH) 三元组存在两套自相矛盾的解**

同一终态账本 `{Ga³⁺ 0.253447, [Ga(OH)₄]⁻ 0.743147, [Ga(OH)]²⁺ 0.003406,
Na⁺ 3, Cl⁻ 3}`，账本自身的电荷条件（Na⁺/Cl⁻ 相消）唯一确定：
`Σz·n(除 H⁺/OH⁻) = +0.0240068` ⟹ `[OH⁻] = 0.024 M` ⟹ **pH = 12.380**。
而 `estimate_pH(该账本, He=-0.024007) = 12.3803` —— **分毫不差**。
⟹ **走步口径的自洽解就是 pH 12.380，且与账本电荷条件一致。**

但引擎**实际报出** `pH = pH_solver = 1.62`、`H_excess = 0.0`：
* 起因为呈现层 `_presentation_He`（engine.py L2165–L2200）的"幻影碱归零"闸
  （账本阳离子羟基离子积超 Ksp 3 个数量级即把 He 判为幻影并**归零**）；
* 归零后 `estimate_pH(ledger, 0.0) = 1.6197`，与电荷自洽值 **12.380 相差
  10.76 个 pH 单位**。
* 即**同一个账本在 He≈−0.024（真）与 He=0（被改写成）两个质子账目下，
  pH 在 12.38 与 1.62 之间跳变**——两套解都"算得出来"，但只有 12.38 与
  账本电荷条件自洽。

**`estimate_pH` 的硬阶跃（独立实测，`tools/heaxis.py`）**：
```
He=-0.05 → pH 12.699     (强碱分支，与 [OH⁻]=−He/V 自洽)
He=-0.02 → pH  1.3109    ← 跳 −11.388 个 pH 单位
He=-0.001 … He=+1e-4 → 全为 1.310882（完全平台 ⟹ 分支硬切换，非数值噪声）
```

**为什么"归中接力"从不发生（原 §3.1 三问的答案）**：
* 终态 `[Ga(OH)₄]⁻ + 4H⁺ → Ga³⁺` 在**引擎自报 pH=1.62** 上 S=+13.305，
  但 `x_max=0.743147`、**`ext` 仅 0.00608**（被账本游离 H⁺ 0.024/4 卡死）
  ⟹ 接力腿"有力气但没有质子可用"（`tools/f31_extent.py` 定影）。
* 同一账本在**走步口径 He=-0.024007** 下 `estimate_pH=12.3803`，该腿
  S=+29.738、`ext=4.39e-08` ⟹ **同一个 (ledger, 反应) 在两个 pH 口径下
  S 相差 16 个数量级**。终态 (ledger, He, pH) 三元组**引擎自己都无法自洽**。
* `_strong_keys`（engine.py L1288）把该腿按 `零推进` 字符串排除出联立
  ⟹ `joint_tries=0`：**能修它的机制恰好被标签关在门外**（D15 的典型形态）。

**⭐⭐ 最根本的一层（第 203 轮收尾定影）：精确解**存在**，只是被**接线闸**挡掉

`tools/chargeprobe.py` 实测（同一账本、同一进程）：

| 状态 | `acidbase.charge_pH`（精确质子条件） | `speciation.closed_pH` | `speciation.exact_proton_pH` |
|---|---|---|---|
| 起始态（3 eq 碱，全 Ga³⁺） | **14.4771 ✓** | None | **None** |
| 中间态（0.5 镓酸根） | **14.0000 ✓** | None | **None** |
| 引擎终态 | **12.3803 ✓** | None | **None** |

* `charge_pH` 在**每一个**状态都给出正确解（终态 12.3803 与账本电荷自洽值
  分毫不差），但引擎实际查询的两个包装 `closed_pH` / `exact_proton_pH`
  **全部返回 None** ⟹ 走步只能退回启发式分支 ⟹ 10.76 单位的错。
* **挡掉它的是 `speciation.py` L1191（`exact_proton_pH` 的 B3 判据②）**：
  ```python
  if m > X_MIN and sp in res_set:      # res_set 含"Ksp-OH 水解阳离子"
      return None                      # ⟹ 拒绝精确解，退回启发式
  ```
  `Ga^{3+}` 因是 `ksp` 表中 `Ga(OH)₃` 的阳离子而落在 `res_set` 里，
  浓度 0.2534 > X_MIN ⟹ **精确解被拒**。
* **但该闸的原设计理由（L1166-1169 的 L08 例）说的是**"这些体系的 pH 由
  Ksp 决定，账本内的质子条件看不到它们"。而 F31 里**根本没有固相在场**
  ——此时 pH 是**自由变量**，账本质子条件**恰恰是**权威解。
  用 `charge_pH` 得到的 12.380 代入沉淀候选得 **S = +25.013**
  （强过饱和 ⟹ **它正是会告诉走步"该析出固相"的那个读数**）。
  ⟹ **闸门挡掉的正是能治好本例的读数。**

**对照 PHREEQC 的做法（`thirdparty/phreeqc-3.8.6-17100/src/model.cpp`）**：
PHREEQC **根本不做 pH 分支估计**——
* 把 pH 当作**未知量**，与所有未知量一起进 Newton-Raphson
  （`model.cpp` L105 `while ((r = residuals()) != CONVERGED)`）；
* **电荷平衡是残差向量里的一条方程**
  （L325-332 "Charge balance has not converged"；L3841-3846
  `if (ph_unknown == charge_balance_unknown) residual[i] += x[i]->moles`）；
* 初值只给"H⁺ + OH⁻ 的总碱量"（L4613-4616），**后续全靠迭代**。
⟹ 成熟解法的性质是"**pH 由守恒方程解出、全场只有一个解**"；我们的
`estimate_pH(ledger, He)` 是**双输入的启发式分支**，这才是阶跃与两套解的根源。
**修法方向因此从"打补丁"升级为"补上无分支的精确解通路"**（见下）。

**修法方向（下一轮首选，已升级为"接线 + 窄化闸"）**：
1. **首选（针对本轮定影的根因）**：让走步在**无固相在场**时使用精确质子
   条件解（`acidbase.charge_pH`）而不是启发式分支。最小改动点：
   `speciation.exact_proton_pH` 的 B3 判据②（L1191）把"Ksp-OH 阳离子在场"
   收窄为"**固相在场**（或有 pinned 储库）"——后者才是该判据的设计意图。
   **必须先用 L08 型验证不回归**：判据②的注释明写 L08 的机器 5.80 由
   Cu(OH)₂ 的 Ksp 定、质子条件会给错的 11；要确认 L08 类是否**有固相在场**
   （若有，则收窄后它仍被正确拒掉，改动安全）。
2. **次选（更保守）**：不动判据，只给 `estimate_pH` 加**自洽性断言**——
   当启发式 pH 与账本电荷条件差 > ~2 个 pH 单位时，改用 `charge_pH`。
   这条不改变其余档位行为，风险最低，但只是"兜住"而非"根治"。
3. **配套（防伪根）**：`solve_extent` 的二分加**阶跃保护**——括号内 `S(x)`
   跳变幅度远超单调预期时判为**伪根**（本例 x∈[0.743,0.75] 内 S 由 +30 跳到
   −13），改走精确解或收窄括号。可复用 `_audit_bracket`（engine.py L294）。
4. **验收**：F31 `has Ga(OH)_3 ≥ 0.9` 通过、pH ∈ [5.0, 7.0]（严格解 5.764）、
   断言 PASS、**其余族不翻红**（重点：Al 三例 H43/H45/M03 与 §0 族扫的
   102 例正常例，以及 L08 型储库例）。

**⭐ 族扫结论（第 203 轮子代理实测 109 例，工具 `tools/fam_hydroxo.py`）**：

  ＋ `H43 AlCl₃+NaOH 1:3.5`（固相 0.000211 / 要 ≥0.3）、
  `H45 Na[Al(OH)₄]+½HCl`（0.00046 / ≥0.3）、

  Al 三例碱过量（碱侧收尾）。

  （pH 6.269）、`N10 CrCl₃+3NaOH`→Cr(OH)₃ **0.9999995**（pH 7.342）、
  `H48 FeCl₃+3NaOH`→Fe(OH)₃ **1.0000000**（pH 7.0，仅 3 迭代）、

  外加 Sc/Y/Nd/Gd/Ho/Tm/Rh/Ru 等 9 个三价金属全部 OH/M=3.000 正常。
  **它们走的第一步与 F31 完全相同**（`M³⁺+4H₂O→[M(OH)₄]⁻+4H⁺`, ext≈0.749，
  同一个"碱限幅 ~0.75"），区别只在**随后能否经 `[M(OH)₄]⁻+H⁺→M(OH)₃`

  0.0002~0.0005（"在场却被阉割"）。
* **所以真正该修的是 `零推进` → `_strong_keys` 的排除逻辑**
  （engine.py **L1285–1290**）：驱动方向反应物**在场**且 `ext_max` 可观
  （Ga 0.743 / Al 0.036~0.089）的腿，被这个标签从**联立求解器与复活路径**
  里剔除了。F31 的两条救命腿（decomplex、再沉淀）**都被同一标签杀死**。
  这与上面"`estimate_pH` 分支切换"是**同一现场的两个环节**：错误的 pH
  把 S 判反 ⟹ 腿被标 `零推进` ⟹ 唯一能纠正它的机制被关在门外。
* ⚠️ **`no-cands` 不是诊断特征**：108/109 例正常收敛也走 `no-cands`
  （含 H48 仅 3 迭代即正确）。要判缺陷必须**组合**：固相缺失/极低
  ＋羟合配合物占溶解金属 >85% ＋有 |S|>3 的两侧腿被标 `零推进`。

**一条重要的口径教训（写进 lessons 候选）**：
探针导出的 `probe["pH"] / H_excess` 是**呈现口径**（过了 `_presentation_He`
的幻影碱归零闸），与**走步口径**不是同一个数。用探针的 pH 去复算 `S` 会
得到与走步不同的值（本例同一账本 1.62 vs 12.38，S 差 16 个数量级）。
**诊断走步必须同时取两个口径**：`probe["pH_solver"]` 与
`estimate_pH(ledger, probe["H_excess"])` 并注明用的是哪个。

**通用性待定（子代理测量中）**：Al³⁺/Cr³⁺ 等三价金属氢氧化物族是否同病。
判别特征：`exit=no-cands` + 迭代数极低 + 账本由羟合配合物主导 + 标 `零推进`。

## 3. 下一步（**优先级最高，已定位**）

### 3.0 ⭐ **Pitzer 修正（使用者特别指出：后续需落实）**

**现状（第 203 轮核实）**：`chemkit/data/pitzer.json` 已有 **426 条结构化 Pitzer
参数**（`b0` 84 / `b1` 77 / `b2` 19 / `theta` 58 / `psi` 165 / `zeta` 17 /
`lamda` 6，来自 pitzer.dat / frezchem.dat / ColdChem.dat / Concrete_PZ.dat），
但 **引擎零消费**（`chemkit/*.py` 里检索 `pitzer|PITZER` 无命中）——是**死数据**（D4）。

**为什么要做**：当前活度层是 **SIT**（`Δz²·A√I/(1+1.5√I) + ε·I`），
其适用上限约 **I ≤ 3–6**；而库内用例有 1 M 级电解质（I 可达 6+），
**高浓卤水区间只有 Pitzer 才准**。数据已就位 ⟹ 这是"数据等引擎"的典型。

**落实方案（建议分步，每步可独立验收）**：
1. **建 Pitzer 活度模块**（如 `chemkit/pitzer.py`）：实现
   `lnγ± = lnγ(DH) + Σ_j m_j·(2B_Mj + Z·C_Mj) + …`（β⁰/β¹/β² 与 Cφ 的
   标准 Pitzer 形式；θ/ψ 为混合项、λ/ζ 为中性-离子项）；
2. **接线点**：与现有 `logK_T(c, T_K, I)` 同层——把"离子强度修正"抽象成
   `activity_model ∈ {SIT, Pitzer}`，按开关切换（`CHEMKIT_ACT=pitzer`），
   这样可**逐族对拍**（同用例跑 SIT/Pitzer 两版，比较 pH 与形态）；
3. **验收判据**：① 高浓用例（1 M NaCl/NaClO₄ 介质）的 pH 与文献锚比较；
   ② 与 SIT 版逐例 diff，位移方向应符合 Pitzer 的已知行为（高浓下
   β¹ 项使 γ 回升）；③ 全套件指标不得比 SIT 版更差（iters/resid）。

**依赖与风险**：① 需要 Pitzer 的**温度依赖**（库内部分条目带 T 多项式系数，
已在 `vals` 里原样保留）；② 需要**电荷/离子配对**匹配（库用 PHREEQC 命名，
需 `tools/phq_parse.py` 的映射）；③ 实现量大，建议**先只在 `I > 3` 启用**
（SIT 在低浓已足够），降低爆炸半径。

## 10. 纪律（不可违背，详见 lessons.md / discipline.md）

* **一切以化学事实为准**；不为迎合测试标准而舍弃更本质的做法。
* **不凑合**：不用指标不治本的小补丁；根源解法暂时失败也不直接抛弃
  （第 198→199 轮即此范例：pinned 首版变差，查明病根后修好而非回退）。
* **数据与引擎缺陷分开记账**，不许互相掩盖（`db_matrix` 出清单）。
* **测试库标准可能有错**：先问"这是化学事实，还是某次引擎输出的快照"——
  但本轮核对的 E55/N22/T51/16 标准都是化学事实，不许动。
* 一切数据改动走 `dev.py patch` 或 `tools/jsondb.py`（**按键路径**，不用文本锚串）。
* 记忆值**不得**当已核数据：查不到出处就**不入库**，或写
  `calibrated: provenance 未核实` 并单列待复核。
* 每轮：**建/更新 todo**、一次运行**全量结构化留档**（`logs/`）、
  轮末入档 `log.md` + 更新 `lessons.md` + 提交 + 汇报指标。
* **子代理使用纪律**（使用者明确要求）：测量/实现类任务派给 coder 子代理
  （`resume="agent-0"` 续用）以省主上下文额度；**子代理返回结果后立即
  终止、不挂空转**，需要续跑再 resume。
* **handoff.md 更新时机**：每轮完成后、以及轮内**阶段性目标**完成后都要
  即时更新（§0 指标、§3 任务状态），不留到轮末补记。
