# `agents/` 是什么（AI 侧工作记忆地图）

> **这不是给使用者看的文档**。使用者文档从 [`../docs/index.md`](../docs/index.md) 进入，
> 项目简介见 [`../README.md`](../README.md)。
>
> 这里是"在同一仓库上继续工作的人/AI"的记忆：**动手前先读，收尾必写**。
> 目标是**不重复付费**——同一件事不发现两次，同一个坑不踩两次。

## 五个文件，各管一件事

| 文件 | 管什么 | 什么时候读/写 |
|---|---|---|
| [`README.md`](README.md) | **本文件**：地图与阅读顺序 | 第一次进来；忘了谁管什么时 |
| [`lessons.md`](lessons.md) | **经验索引 + 工作方式**：缺陷类别 D1~D10、工具/编码坑、被实测否掉的方案、数据与文献纪律、每轮固定动作 | **每轮开始先扫一遍**；踩到新坑或否掉方案时**立刻加一行** |
| [`discipline.md`](discipline.md) | **纪律条文**（规则式、短）：数据改动路径、测量纪律、断言门槛、分账纪律、发版硬门槛 | 动手改数据/改标准/发版前 |
| [`tools.md`](tools.md) | **命令与工具手册**：`dev.py` 子命令、分层测试协议、结果留档与读取、工具创建规范、审计工具与诊断开关 | 要敲命令时（先查有没有现成工具） |
| [`log.md`](log.md) | **当前期工程日志**（按轮次追加，只增不改） | 接手某块代码前检索相关小节 |
| [`log-archive.md`](log-archive.md) | **早期归档**（第 146 轮从 `log.md` 拆出，内容逐字保留） | 查早期轮次/X 编号小节 |

## 阅读顺序（推荐）

1. `lessons.md` 第 1 节（缺陷类别）——知道这个项目**最常犯什么错**；
2. `lessons.md` 第 5 节（工作方式）——本轮该怎么走；
3. `discipline.md`——动手时的硬规则；
4. `tools.md`——命令怎么写、什么时候**不必**跑全量；
5. 需要历史细节时，按 X 编号在 `log.md` / `log-archive.md` 里检索。

## 写日志/教训的三条自约定

* **只写"下次能省时间"的东西**：现象 + 实测数字 + 结论，不写过程心理活动。
* **数字必须可复核**：写清探针名/命令/用例名，别人能重跑。
* **不确定就标明不确定**：猜测写成"疑似/待验证"，不要混进结论。

## 与其他目录的边界

* `docs/`：**给使用者**的文档（架构、API、数据、测试、性能、局限、changelog）。
* `tools/`：耐久工具（可复用、有 CLI、结构化输出）；一次性探针用 `_*.py` 放仓库根，
  且**尽量扩展现有探针而不是新建**（见 [`tools.md`](tools.md) 的"工具创建规范"）。
* `chemkit/`：引擎与数据；`chemkit/data/*.json` 的增改只能走 `dev.py patch`。
