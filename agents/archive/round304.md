## 一、为什么先做"不变量检查"而不是先修 bug

审查报告的核心结论是：**套件通过率这个数字不可信**。它同时包含
"输出错误但判对"（T9a 的 4 例）与"输出正确但判错"（T4 的 2 例）。
在这个前提上做任何优化决策都可能反向。所以第一步是建立**不依赖真值**的检查。

新增 `chemkit/helper/invariants.py`（三条，均可作为发版门槛）：

| 检查 | 判据 | 为什么它永不过期 |
|---|---|---|
| ① **尺度不变性** `scale` | 同浓度、同配比，改体积 ⟹ pH/浓度/degree 不变 | 体积是热力学无关变量，与真值无关 |
| ② **进程确定性** `det` | 同一输入在多个 `PYTHONHASHSEED` 下逐位相同 | 逻辑同一性，不需要外部数据 |
| ③ **输出守恒** `cons` | 引擎**输出**的净方程/分步方程元素+电荷守恒 | 与 `eqcheck` 互补：后者验期望式，前者验实际输出 |

用法：
```powershell
python -m chemkit.helper.invariants            # 三条全跑
python -m chemkit.helper.invariants cons       # 只跑守恒
python -m chemkit.helper.invariants scale --all
```
退出码 0/1，可直接进 CI。

## 二、本轮修复（6 项）

### R1 确定性：`normalize._anion_order`（T8a）

**病灶**：`_split_salt`/`_split_acid` 里 `for an in T.anions` 遍历的是 `set`，
而两者都是"首个匹配即返回" ⟹ 同一物种在不同进程拆成不同离子组。

**实测**（`H_3PO_4`）：`seed=0 → H^+ + H_2PO_4^-`、`seed=1 → 3H^+ + PO_4^{3-}`

**修法**：新增 `_anion_order(T)`，排序键 = `(电荷绝对值, 元素数, 化学式)`。
键的选择让**逐级电离优先于一步脱光**，即 `H_3PO_4` 必然得 `H^+ + H_2PO_4^-`。

**验收**：3 个 seed 输出完全相同，且都是逐级电离形式。

### R2 确定性：`converg._canon`（T8b）

**病灶**：`_result_digest` 对 dict/list 直接 `json.dumps`，键序来自
`set(ledger) | set(gas_phase)` ⟹ 摘要随哈希种子变。`sort_keys=True`
只排字典键，对**列表元素顺序**无效。

**实测**：4 个 seed 得 **4 个不同 digest**（逐字段比对确认数值全同）。

**修法**：新增 `_canon()`，进摘要前规范化——dict 按键排、list 递归后按
`repr` 排、浮点统一到 12 位有效数字。

**验收**：4 个 seed 得 **1 个 digest**。

### R3 输出守恒：`_fold_pools` 不再凭空删原子（T9a）

**病灶**：
```python
consumed[lig] = consumed.get(lig, 0.0) - x     # lig 不在该侧时变负数
if consumed[lig] <= 1e-9: consumed.pop(lig)    # 随即被静默删除
```

**实测**：`D43 Cl2+石灰乳` 在 n≥0.05 时净方程缺 6.44 mol Cl（相对 0.35%），
且**该错误结果已被写进 `tests.json` 的 `eq` 标准**。

**修法**：减法必须落在一侧——若跨零点，余额以相反符号搬到另一侧。

**验收**：n=0.01…2.0 六个量级全部守恒，方程恢复为
`Ca(OH)2 + Cl2 -> Ca2+ + ClO- + Cl- + H2O`。

### R4 判据加严（T9c 的一部分）

| 位置 | 原判据 | 新判据 |
|---|---|---|

| `_beautify_covers` | `keep ≥ frac·total`（两个 `×0.5` 相互抵消，注释说的"投向两侧较小者"根本不存在） | 先按系数尺度还原到摩尔量，再按 `min(消耗侧, 生成侧)` 度量 |

### R5 分步方程缺 H₂O（审查清单外的新发现）

**病灶**：`_step_to_ionic` 里 `_restore_oh` 会把 `H^+` 改写成 `OH^-`，
这一步改变 H/O 原子数，而之后**没有再配平**就返回。
症状高度一致：`H 左1 右2、O 左0 右1`（40 例中 17 例）。

**修法**：还原后再调一次 `_balance_h_o`。

### R6 瞬态折叠的 extent 尺度错误（审查清单外的新发现）

**病灶**：`_collapse_transient_intermediates` 折叠中间体后把 extent 设成
`max_amt`（毛量），而 `net_r`/`net_p` 已经是**乘过 extent 的摩尔量**
⟹ `_step_to_ionic` 又乘一遍，配平补项按旧尺度加 ⟹ 彻底错位。

**实测**：`X33 AgCl+过量NaSCN` 折叠后得 `1.009SCN^- + AgCl -> Cl^-`
—— **AgSCN（主产物）整个消失，Ag/C/N/S 四种元素凭空没了**。

**修法**：`extent = 1.0`（净量已含 extent）。折叠后正确得
`AgCl + SCN^- -> AgSCN + Cl^-`。
