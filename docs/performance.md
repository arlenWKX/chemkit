# 性能

## 1. 口径：裁决性能改动用确定性计数，不用墙钟

共享/沙箱环境里墙钟的第一遍惩罚可达 **27%**：同一份代码在同一进程内跑三遍
全量得到 53.6 s（首遍）/ 40.3 s / 42.1 s（`tools/sof_ab.py`，首末两遍是同
一份**旧**代码，`iters`/`steps`/逐例 digest 完全一致）。所以跨时间比较均值
（"这轮 30.8 还是 33.9 ms"）没有意义。

**硬指标**（同一份代码 ⇒ 同一计数）：

| 指标 | 含义 |
|---|---|
| `sof_total` | `S_of` 调用次数（每次二分探针一遍 pH/形态/枚举/评估） |
| `iters_total` / `iters_p99` | 走步迭代数（总量 / 99 分位） |
| `steps` | 实际执行的步数 |
| `resid_p50/p90/max`、`n(\|S\|>1)`、`n(\|S\|>0.1)` | 出口残差画像（live 残差口径，见下） |
| `digest_all` | 逐例输出摘要（**辅助信号**，不是门槛） |

**残差口径 = "求解器承诺要解、且真的没解掉"的两侧平衡**（`engine.resid_live_ok`
单一定义）：两侧物种都在场 ∧ 非 slow/blocked ∧ 可动量 `ext_max ≥ 1e-3`
∧ **未真正达到平衡**。最后一条含一个反直觉但关键的规定：

> **冻结 ≠ 已达平衡。** 冻结是防震荡手段（极限环/实测仲裁），不是"这条通道平衡了"
> 的结论。走步曾把二者混同，于是冻结集成了质量口径的盲区——N30/D32 的
> `Fe³⁺ + 3SCN⁻ → [Fe(SCN)₃]` 两侧在场、`|S| = 4.02`、可动量 0.167 mol，被冻结后
> 以 `no-cands` 退出，指标却报另一条 `|S| = 0.0 / 已达平衡` 的候选 ⟹ 全绿而化学
> 错在主产物上。现在只有 `|S| ≤ 0.1`（与 `n(|S|>0.1)` 同一把尺子）的冻结通道才
> 豁免。修口径后 `n(|S|>1)` 由 22 → **44**、`n(|S|>0.1)` 由 56 → **101**：
> 这就是此前被冻掉的真实欠收敛规模（`tools/frozen_audit.py` 提供逐条来源）。

逐例判读同理：**不要用 dump 里的 `ms`**（含 GC 停顿，单例可被放大数千倍），
用 `iters` / `steps` / `sof`。

## 2. 当前基线

权威来源是受版本控制的 `converg-baseline.json`（`python -m chemkit.testsuit perf --write`
刷新，`python -m chemkit.testsuit perf` 与 HEAD 逐项对账）：

| 指标 | 值 |
|---|---|
| n | 1378 |
| iters_total | 16217 |
| iters_p99 | 146 |
| sof_total | 1276641 |
| resid_p50 / p90 / max | 0.0 / 0.015 / **10.036** |
| n(\|S\|>1) / n(\|S\|>0.1) | 33 / 88 |
| digest_all | `fe15ddf367b33414` |

墙钟（仅参考，不作门槛）：均值 **30.6 ms**、中位 15.0 ms、P90 47.8 ms
（含首个判定的静态层构建 ~3 s 一次性摊销）。

**这一版与前几版的区别**：为把"冻结集里的强驱动通道"真正解掉（见
[`limitations.md`](limitations.md) §6），走步要多花 **+16% 迭代 / +15% S_of 调用**
——换来 `n(|S|>1)` **39 → 29**、`n(|S|>0.1)` **95 → 68**、`resid_max`
**32.0 → 7.1**。这正是"性能手段的隐性代价"（[`../agents/log.md`](../agents/log.md) X-39）
的对账方式：**先问它藏了什么，再问它省了多少**。

残差尾部的构成（`tools/frozen_audit.py` 与探针 `resid_src` 可逐条查来源）：
`|S|` 最大的一批多为**痕量伪驱动**（`ext_max ≈ 1e-3` 的反应物池 + 巨大 `|S|`，
如 Cu(I) 痕量物种）；真正需要化学裁决的是**可动量大且 `|S| > 1`** 的那一批。

## 3. 静态层与长期运行

首次判定时构建：电对配对、Hess 派生候选（万余条）、红氧模板与枚举 memo；
之后跨判定驻内存复用。**推荐用法是进程内建一次 `Engine` 长期复用**，
同温度判定命中热路径。

## 4. 已定位但被判否的优化（别再走一遍）

| 路线 | 实测 | 判否理由 |
|---|---|---|
| 保括号假位法（Illinois）替换二分 | 求根求值次数 **2.04×** 减少 | 2.6% 的括号里 `f` 有"−/+ 口袋"（近似 pH 机器换分支造出的伪结构）；二分返回**最左根**＝第一次 S=0 的停止点，假位法会跳进口袋上方收敛到**第二个**穿零点 ⟹ **过执行**（某例 0.016→0.027）。不是测试被锁，是求根法本身错 |
| 循环键子集联立求解 | — | 子集不动点 ≠ 仲裁点，语义翻案 |
| 整个活性社区联立求解 | 某例 11 → **3010** 步 | 候选集跨数据源 Hess 互斥无解 |
| 一维几何外推加速爬行 | — | 慢例是**螺旋**不是直线，有效域就是微步档 |
| 减少步数（四条路） | — | 逐候选贪心是结构性代价，见 `agents/log.md` M/T/U 节 |

**下一步的主攻方向**（也被上表证伪）：让 pH 由**一套平衡条件**决定，消除
分支切换造成的 `pH(x)` 不连续（普查：23.2% 的求根括号里 pH 相邻点跳变
>1.0 单位、20.4% >3.0，最大 9.10，集中在两性/固相族）。
